## Notes for the maintainer
- Verification (both OSes): GitHub HTTPS, length vs. GitHub's listed size, and (new) the SHA-256 GitHub lists per asset (`digest`; checked live: 0.54.0 assets have it). No digest (older releases): length only, logged. Mismatch: refused with a plain error, nothing installed. Linux also checks ELF + CPU type (Windows: "MZ").
- Restart: Linux re-execs the new program in the same process (systemd sees no stop). If exec fails under systemd it exits 75 (unit has Restart=on-failure). Windows paths unchanged.
- Differs from Windows: `hopperd.old` is kept after the restart (Windows deletes its .old at start).
- Running servers (Linux only): Windows reattaches to running servers after a panel restart (`LocalServer::reattach`, windows-only), so its behaviour is unchanged. Linux has no reattach, so every Linux update (auto, Update now, rollback) waits until no server on the panel is running ("Update ready: waiting for 2 running servers to stop…", re-checked every 3 s). Update now / Update to X / Roll back, with servers running, asks first, naming them: "Stop servers and update" (normal stop, saves worlds, then updates; they are NOT started again) or "Wait for them to stop". While waiting, the card offers "Stop servers and update". The API never stops a server unless the request says `stop_servers: true`. A 24/7 server means auto-update waits until it is stopped.
- README still says Linux hopperd doesn't reattach; true, and now covered.
