# Mod pages can't crash on odd descriptions or file names; links, italics and strikethrough show right

**Branch:** t3/mod-page-robustness   **Commits:** 962d8e7 (crashes), 182aeec (rendering)   **Size:** M
**Apps:** both. The desktop renders descriptions. Hopper Server's web UI uses the same parser in `hopper-core` and gets every fix; strikethrough also needed a small change in the web UI.

## From -> to
- Before: on Modrinth, reference links showed as `[text][16]`, `<https://…>` links vanished, `_italic_` and `~~strike~~` showed their marks, and a `<` before a number ate the rest of the sentence. A Files tab on a mod with a non-ASCII file name, or a description ending in `<`, could crash the app.
- After: all of these render like on the website, and the crash paths are fixed and covered by tests (random and hostile input included).

## Crashes found (all fixed, all tested)
| Where | Trigger | Effect before |
|---|---|---|
| `sources::mc_versions` (peek Files tab, through `sources::files`) | file name with a non-ASCII character before "1." (`模组-1.21.jar`) | byte-slice panic inside a GPUI background task: **whole app aborts** |
| `richtext::parse` (CurseForge HTML) | description ending in `<` (or `<` + multi-byte char, no `>`) | `&rest[1..0]` panic |
| `anim::frames` (GIF/WebP in descriptions) | GIF/WebP claiming e.g. 65535x65535 | ~17 GB allocation per frame: abort. Now capped at 4096x4096; bigger ones aren't animated |
| image `width`/`height` attributes | `width="99999999999"` | overflow in thumbnail size math (debug build). Capped at 8192 |
| list / link nesting, `[` runs, `&lt;` runs | hostile input | deep recursion; quadratic time (30k `&lt;`: 9 s, now 0.17 s; 20k `[`: bounded at 4 KB scans) |
| version sorts (`scan::compare_versions`, `selfupdate::compare`) | none found | both checked by property test for total order (Rust 1.81+ sort panics otherwise) |
