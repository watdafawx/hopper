# Syncing to a Hopper Server no longer hangs on a bad connection, and the Tasks bar shows the upload

**Branch:** t3/fix-remote-sync-upload-hang   **Commits:** 1d32e30, 1aa759f   **Size:** M
**Apps:** both (desktop client + Hopper Server routes; web UI wording only)

## From -> to
- Before: a sync to a remote Hopper Server sat at "Syncing 1 files" forever when a chunk's connection dropped (the panel answered a plain-text 400 nobody logged; the client waited up to an hour for a reply). "Adding N mods to the server" sent each jar in one request with no reply limit and one try.
- After: every chunk has send/reply limits, up to 5 tries with backoff, re-sends are safe (the panel writes only what it lacks), and the panel logs a WARN with the reason. Adding jars uses the same resumable chunks, then one small call (3 tries, checks whether a lost reply already added it). Both end with a plain error instead of hanging. The Tasks bar follows the bytes sent. Counts read "Syncing 1 file", "1 mod copied".
