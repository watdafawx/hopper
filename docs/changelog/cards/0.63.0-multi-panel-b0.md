# Hopper Server: other web pages that may use a panel, and a locked-down web UI

**Branch:** t3/hopperd-panel-origins-csp   **Commit:** 77ddc43   **Size:** M
**Apps:** Hopper Server only (desktop has no web UI or CORS; nothing to match)

## From -> to
- Before: the web UI had no Content-Security-Policy, and no other web page could call a panel's API from a browser (no CORS at all).
- After: the web UI carries a strict CSP (scripts only from the panel's own files). The owner can list other web pages (exact addresses) that may use the panel, in Settings › Access & devices; those pages get CORS and must sign in with a token. A switch, off by default, decides whether those pages may also manage users, devices, tokens, two-factor and the certificate. The list and the switch only change from the panel's own page.

## Security evidence
- CSP header on every UI response (`/`, `/index.html`, deep routes, `/logo.svg`), plus `X-Frame-Options: DENY`. Walked 24 server routes and 11 settings pages in Chrome with the console open (incl. CodeMirror editor, mod icons from media.forgecdn.net / cdn.modrinth.com): zero CSP violations. First policy (style-src-elem 'self') broke the editor's injected `<style>`; changed to `style-src 'self' 'unsafe-inline'`, re-walked clean.
- CORS (evidence-curl-1.txt / -2.txt): listed preflight 204 with exact allow-origin, methods, headers, max-age 600, PNA `true` when asked; unlisted / empty list preflight 403, no CORS headers; listed GET gets allow-origin + expose + `Vary: origin`; unlisted GET only Vary; no Origin, no CORS headers; never `*`, never Allow-Credentials. 25 preflights to /auth/login: all 204, sign-in limit untouched.
- Two scratch panels (8861, 8862), page on 8861 calling 8862 in Chrome: unlisted -> fetch TypeError, OPTIONS 403. Listed -> read-only token GET /servers 200, body readable. Switch off -> POST /users, POST /tokens 403 with the guard message; PUT web-access 403 "Change this on the panel's own page."; POST /servers/rescan 200. `credentials:'include'` cookie ride: blocked. Switch on (set on 8862's own page) -> POST/DELETE /users 200; read-only token still can't make tokens; PUT web-access still 403.
- Audit log records every change ("added http://127.0.0.1:8861", "other pages manage access: on") and each 403.

## Notes for the maintainer
- No separate HTML mock: the card copies the existing API tokens card layout (rows, add field, switch row).
- style-src allows inline styles (Svelte + CodeMirror). Upgrade path: per-response style nonce.
- Capability advertised is `web.origins`; `web.remote` waits for B1 (bearer browser sessions).
- Not in the guarded list (candidates for B1): backup-receive keys, SFTP-related settings.
- Listed origins lose their Cookie header on the way in, so a listed page can never ride the owner's cookie.
