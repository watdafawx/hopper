# Missing-mod notice: names and installs the right mod

**Commit:** 9d78abbd (released in 0.90.4 and Hopper Server 0.80.2)   **Size:** S
**Apps:** both. The lookup is shared in the core library, so desktop's notice, Install and the mod page, and Hopper Server's install of a missing mod, all pick up the fix.

## From -> to
- Before: "1 required mod is missing" named `Foundation` (a different CurseForge mod that happens to have the id `foundation`) for TNP Limitless 8, while the mod page showed the right one, [Let's Do] Foundation. Install would have fetched the wrong mod too.
- After: the notice, Install and the mod page all use the mod the asking jar lists as required, so they agree.

## Tested
- Test build on rig, throwaway instance only. The notice read "[Let's Do] Foundation (for WilderNature)" with the right icon. Install added `letsdo-foundation-neoforge-1.1.0.jar` and its dependency Architectury, not the other Foundation.
- A core test covers the name rule (prefixed pages match; ids under 5 letters never do).

Not checked: Hopper Server's own install button on a scratch panel (same core lookup), other themes, a mod whose id is a plain word with no prefixed page.
