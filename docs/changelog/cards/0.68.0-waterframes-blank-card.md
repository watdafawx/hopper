# Crash card: missing dependency gets an Install button (Hopper Server)

**Branch:** t3/waterframes-blank-crash-card   **Commit:** see `git log` on the branch (one commit)   **Size:** M
**Apps:** Hopper Server (web UI + API). Desktop untouched: it already had Install / Installed. Shared `need_status` helper lives in hopper-core so desktop can adopt it later.

## From -> to
- Before: a crash from a mod that needs a missing mod (WaterFrames needs WaterMedia) showed "Needs watermedia" with no way to fix it in Hopper Server; the desktop had an Install button.
- After: each missing need shows "Needs X" + an **Install** button (Modrinth/CurseForge lookup by mod id, logged to History). Done state: "Installed" tick and the step text changes to "It has what it needs now. Start the server to try again." Loader/Minecraft/Java needs say "Change it in the loader versions" instead of an Install button.

## Root cause of the blank card: NOT reproduced
Tried to reproduce on the pre-boundary build (ecbbcbc) and on the boundary build (cb8162e), with the real WaterFrames crash report + `latest.log` copied into a scratch server (plus 500+ stub jars in `mods`, matching mtimes, grouped repeats, many reports, light + dark, narrow windows). The API returns a normal Mods-kind crash with one Certain suspect; the card draws in full every time. No exception in the browser console.
- The boundary from cb8162e stays as the safety net.
- Not ruled out: real `/mods/list` shape on the user's server, running/crashed server state, 0.57.2 build differing from source, very short windows (700x500: `.read` area collapses to 0 height, see `before-narrow-700x500.png`).
- Next step if it still blanks on 0.57.3+: open DevTools console on the real panel and send the first red line.
