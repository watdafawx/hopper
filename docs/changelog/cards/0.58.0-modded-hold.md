# Modded players can wait on the connecting screen while a server starts (experimental, off by default)

**Branch:** claude/modded-hold (worktree `.claude/worktrees/modded-hold`)   **Commit:** cfc07d0   **Size:** M
**Apps:** Hopper Server (router + web UI) and desktop (the Sleep settings of a paired panel). Desktop compiles but was **not looked at on screen**.
**Stacked on:** `claude/sleep-wake-visible` (bf4ea6e, not merged). I branched from it so the new row sits in the final Sleep card. My `Sleep.svelte` edit is one state var, one `MODDED` list, one body/stateOf/load line each and one row + hint; it does not touch the wake options block, so it should merge cleanly. If master merges mine first, bf4ea6e comes along.

## From -> to
- Before: a Forge / NeoForge player joining a modded server that sleeps is let into the lobby island handshake, then turned away in the configuration phase (`limbo.rs` brand check) with the "join again" message.
- After: with the new setting on "Wait (experimental)", that player stays on Minecraft's normal "Connecting to the server..." screen until the server is up, then joins by itself. No progress bar. Default is unchanged ("Join again message").

## Where modded players are turned away today (as found)
- `crates/hopperd/src/limbo.rs` `run()` (was l.142-148): after Login Success and the Known Packs exchange it reads the client brand from the config-phase plugin message; `brand` contains "forge" **and** the server is modded -> `config_disconnect(join-again)`; outcome `Refused`. `island()` in `router.rs` then puts `server id/player` in `lobby_refused`, so later joins skip the island and get the kick. "Modded server" = saved ping (`.hopper-ping.json`) says so (`ping_is_modded`), or no saved ping at all.
- Why the island can't do better: NeoForge's mod check starts in the configuration phase, which the island has already entered.
- State the router holds for a join (`router.rs`, `standin()`): the whole handshake + Login Start bytes in `buf` (`end` = where Login Start ends), parsed `Handshake` (`raw_host` still has the Forge marker, e.g. `host\0FML3\0`), player name + uuid, `RouteSettings` read from `.hopper-route.json` per call, `woken: server id -> who` (set when a join starts a Stopped/Crashed server, cleared when it is Running or has failed; `is_waking()`), `lobby_refused`, `wake_failed`/`failed_hold` (a failed wake answers `WakeFailed` before anything else), and `may_wake()` (`wake_who`). All of that is unchanged.

## What I built
- Setting `modded_players`: `kick` (default) / `wait`, in `RouteSettings` (`.hopper-route.json`), returned by `GET .../address`, accepted by `PUT .../address`, shown in the Sleep card (web) and the Sleep settings (desktop).
- Applies only when: setting is `wait`, sleep on, wake-on-join on, a player name, `may_wake` ok, **client is Forge/NeoForge** and the server counts as modded. Client = handshake host carries a `\0FML...`/`\0FORGE\0` marker (`Handshake::is_forge_client`), **or** the player was already turned away as modded by the island this run (`modded_clients`). Vanilla clients keep the island. Fabric clients are not touched (their handshake has no marker; whether Fabric-with-mods needs this is unverified).
- `crates/hopperd/src/hold.rs`: generic async state machine over any stream. Sends a Login Plugin Request (`0x04`, id, channel `hopper:wait`) at once and every 10 s, one at a time; client answers (`0x02`). Ends: server up and the last request answered -> `Ready` (rest of the client's bytes returned); start failed -> `Failed`; 10 min -> `Capped`; client closes -> `Left`; a request unanswered 20 s -> `NoAnswer`; anything but an answer from the client, answer to an unsent id, or >8 KB buffered -> error (dropped). Each write has a 10 s timeout.
- `router.rs` `wait_for()`: takes a hold slot (one per player name and server; max 16 per server; freed by a Drop guard even if the task is cancelled), runs the hold, then connects to the server's port, replays `buf[..end]` (original handshake incl. marker + Login Start) + leftover, lists the connection for the Players tab (as a normal join) and `copy_bidirectional`. Failed -> `wake_failed_kick`; cap -> join-again; backend refuses connect -> join-again.
- Unchanged on purpose: wake_who / failed-wake hold / rate limits; the hold never starts a server (the existing wake code does, before the hold), `progress()` copies the island's "Running && port answers" / "Stopped|Crashed && not waking = failed" test.
- Packets (core): `login_plugin_request`, `login_plugin_response_id`, `Handshake::is_forge_client`.

## What the script proved / what only your client can prove / guesses
- Proved (scripted, protocol level): a modded-marked connection can be kept in the login phase for the whole start by answering-able plugin requests, and handing it to the real server by replaying the original handshake + Login Start works byte for byte; failure, leaving, duplicates, junk are handled.
- Only a real client can prove: (1) the NeoForge/Forge client answers an unknown login query `hopper:wait` with a "not understood" response and does **not** disconnect (I believe vanilla does; NeoForge's own login-query handling is unverified); (2) it keeps "Connecting to the server..." for minutes and not a timeout; (3) after the handover its normal login + mod check against the real modded server works; (4) whether the NeoForge 1.21.1 handshake carries the `\0FML3\0` marker (my detection depends on it; fallback: a first join is turned away by the island, from the second join it is held, because `modded_clients` remembers the player until hopperd restarts); (5) whether the NeoForge client's server list shows the entry as incompatible (the stand-in repeats the saved `neoForgeData`).
- Guesses: the 10 s interval and the 20 s answer limit (client timeout 30 s); the 10 min cap; Fabric needs nothing.

## Notes for the maintainer
- Security: pre-auth path. Per connection: buffers capped (8 KB), every write 10 s timeout, answer deadline 20 s, hard cap 10 min, one connection per name per server, 16 per server, `may_wake` checked before holding, no change to rate limits or to what can start a server. A stranger can still occupy up to 16 sockets per server for up to 10 min when sleep + wake-on-join are on and wake_who allows them; with `wake_who` = whitelist/ops they cannot (their name is checked first). Off by default.
- Island still marks Forge clients as `lobby_refused` as before; the new `modded_clients` set is only used for the hold.
- The setting's wording: label "Modded players", options "Join again message" / "Wait (experimental)", hint as asked (shortened the option names so the segmented control stays on one line in the card).
- Not done: Fabric (unverified), a progress hint to the player (none possible on that screen), the "Join again message" state screenshot, desktop screenshot, a changelog entry.
