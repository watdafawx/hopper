# Servers: turn a panel off, and refresh or retry a slow panel

**Branch:** t3/panel-toggle-manual-refresh   **Commit:** d9fe821   **Size:** M
**Apps:** both

## From -> to
- Before: every paired panel was always asked and always listed; a slow or timed-out panel had no way to ask again except waiting; Settings said "1 servers".
- After: each panel has an On switch (desktop Settings › Servers, web group menu "Turn off" + a "Turned off" footer). Off = zero requests, group and servers hidden, pairing kept. Servers page has a refresh button; a slow (4 s+) or failed panel says so with Try again. "1 server".

## Notes for the maintainer
- Crafty / MCSS / Pterodactyl: off stops all API calls, but their servers also come from the servers folder, so they stay listed in the Folder group.
- A long-poll already in flight when a panel is turned off finishes once (its answer is dropped).
- Web UI (pre-existing): a panel that hangs while its socket stays open is never marked down; pings fail silently ("the socket notices a dead panel"). Only a panel unreachable at connect time shows Reconnecting. Worth a follow-up (mark down on ping timeout).
- Shared files also touched by the multi-panel A3 agent: `src/gpui/servers.rs`, `crates/hopperd/ui/src/ServerList.svelte`, `Shell.svelte`, `lib/panels.svelte.js` (edits kept small).
