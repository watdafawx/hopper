# Followed packs: a failed download and a jar on no mod site get their own words

**Branch:** t3/fix-left-out-wording-merge   **Commit:** 937e5026 (released in 0.89.3)   **Size:** S-M
**Apps:** desktop only. Hopper Server has no followed packs (its "left out" is the client-mods file of a made server, untouched). No Hopper Server release this time.

## From -> to
- Before: the missing line of a followed pack (Friends > On this network) used one sentence for everything, named site files by number, and was wiped by the sharer's next code.
- After: failed downloads and hand-added jars have their own lines, the failed ones are named by mod, and a row stays until its file is here or the pack no longer has it.

## Strings
| Case | Before | After |
|---|---|---|
| 1 failed download, name known | `a CurseForge mod (file 51) isn't on any mod site, so Hopper can't download it. Ask Mia to send it.` | `Hopper couldn't download Sodium just now. It tries again by itself.` |
| 1 failed download, lookup failed | same as above | `Hopper couldn't download a CurseForge mod (file 51) just now. It tries again by itself.` |
| several failed | `A, B, C and 2 more aren't on any mod site, so Hopper can't download them. Ask Mia to send them.` | `Hopper couldn't download A, B, C and 2 more just now. It tries again by itself.` |
| jar with no source (1 / several) | `x.jar isn't on any mod site, so Hopper can't download it. Ask Mia to send it.` | unchanged (own line, under the failed line) |
| sharer's next code arrives | whole list replaced; the failed row vanished | failed row kept while the code still lists that file; sharer's hand-added names replaced by the sharer's new list |
| file arrives later (group read, or put in by hand) | row stayed until the next code | row goes |

Not changed: the task note at apply time (`1 file didn't come in: a CurseForge mod (file 21). Hopper counts it as not received and tries again when it next reads the group's changes.`). It is written before any name is known.

Also changed, behind the lines: one friend's left-out list no longer passes file ids to the group as hand-added jars. The group copy now passes only real hand-added names, so another member is no longer told to expect "a CurseForge mod (file 51)" as a jar.

## Notes for the maintainer
- Side effect, on purpose: `sharers_hand_added` passed the follower's whole `left_out` on to the group, so 0.89.1 could publish "a CurseForge mod (file 51)" to other members as a hand-added jar. It now passes only real hand-added names.
- A failed row is dropped when the sharer's newer code no longer lists that exact file (a newer file of the mod, or the mod removed). If the newer file also fails in a group read, nothing lists it: the group read has its own reporting (`groupsync` unresolved), not touched.
- Rows are per file, not per mod, for CurseForge / Modrinth (the mod is unknown without a lookup); per link for mods from GitHub and other links.
- The incoming-share card and the follow dialog (`friends.rs:1391`, `:3481`) show the sharer's own list, always hand-added jars: unchanged.
- No relay change, nothing downloads earlier, no change to ordering, marks, held changes or the first-code rule. The name lookup is two read-only site calls per follow, only for unnamed rows.
