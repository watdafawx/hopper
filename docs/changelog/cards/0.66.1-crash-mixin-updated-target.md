# Crash card: a mixin into an updated mod names the update (Vista: Advanced Player)

**Branch:** t3/crash-mixin-updated-target   **Commit:** 36886eb   **Size:** M
**Apps:** desktop + Hopper Server (same core; web crash view checked on a scratch panel)

## From -> to
- Before: "Vista: Advanced Player failed to load" (it read like a startup crash), Vista blamed as a suspect, "Update Vista: Advanced Player" offered with no newer version out, and "While you last played" flagged Connectivity and others for refmap warnings.
- After: "Vista: Advanced Player doesn't match Vista". The story says Vista was updated today (5.6.5 → 5.6.8) and Vista: Advanced Player was made for an older Vista. Steps: 1. Turn off Vista: Advanced Player and play. Vista can stay. 2. Or undo the Vista update (may help). Vista row: "Changed by an update: Vista 5.6.8 doesn't have projectorID … Nothing is wrong with Vista itself." Why?: "It looks for projectorID in Vista, which this Vista no longer has." and "The game started fine: … here in the world."
- Same miss again after the rollback (5.6.5, ×2): "Vista: Advanced Player doesn't work with this Vista (tried 5.6.8 and 5.6.5). Turn it off until it's updated." Only "Turn off" is offered, no undo.

## Root causes
1. Nothing read the missing piece of a mixin (`@Shadow field X was not located in the target class C`), so the target mod was just another suspect.
2. Connectivity false positive: LiveWatch ran the full `signals()` on new log lines and kept any hit whose reason mentions "mixin". Connectivity's mixin frame (`redirect$zzl000$connectivity$checkDecodingError`) in a later Netty curios decode trace matched. Now only real apply failures count (`MIXIN_FAILED`/`ERROR`/`ATTACH`). stuckstart.rs has no mixin detection, so no change was needed there.
3. "Update X" was a fixed step. It now drops when the last update check has no newer X (`steps_shown`). With no check, or a mod not from a site, the step stays.
