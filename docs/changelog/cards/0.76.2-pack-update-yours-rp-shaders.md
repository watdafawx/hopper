# Pack update: resource packs and shaders you added count as yours

**Branch:** t3/pack-update-yours-rp-shaders   **Commit:** 1c2d52e   **Size:** S–M
**Apps:** desktop (instance pack update window). Hopper Server: no change needed. Its pack update only covers servers, and servers have no resource packs or shaders. The shared hopper-core code is the same for both.

## From -> to
- Before: if you dropped a resource pack (.zip or a folder) or a shader into the instance by hand, the pack update window didn't list it under "What stays". It only showed up in "Your files" when the pack itself shipped files in that folder. Jars dropped into mods/ by hand were already counted.
- After: hand-added resource packs and shaders (zipped or unzipped, on or turned off) are listed with your mods as "Added by you". The summary names each kind: "1 mod, 1 resource pack and 2 shaders you added". The tab reads "Your mods and packs" when packs are in it.

## Root cause
`packdiff::plan` found hand-added files with `stray_jars(inst.root/mods)`, which only reads `mods/*.jar` (from 00c4bcf). Nothing scanned resourcepacks/ or shaderpacks/. Packs that Hopper had a record of (`Addon`, not `from_pack`) were already counted. Packs it had no record of were not.
A second, smaller gap: `split_made` counted data or resource packs in `config/paxi/datapacks|resourcepacks` and `config/openloader/` as "settings the pack's mods made", so those weren't listed either.

## Notes for the maintainer
- `ModChange` gained `folder` (serde default, skipped when empty), so old saved plans still load.
- The row icon for an untracked pack is the generic cube (no project). Same as untracked jars.
- If a resource pack and a shader have the same file name, both are matched against the update's mod list, which has file names only. In that rare case one could be missed as yours.
