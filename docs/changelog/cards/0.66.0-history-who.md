# History says who made each change

**Branch:** t3/history-sync-actor-attribution   **Commits:** d0fa827, merge 1470962 (main 0.65.0), 813c927 (review fixes)   **Size:** L
**Apps:** both (desktop instance History + Hopper Server mod History)

## From -> to
- Before: History listed what changed ("Turned off Sodium"), never who; turning mods on/off or adding one left no entry at all.
- After: every row starts with the person: "Mia turned off Sodium", "Updated from Robin's All the Mods 10 · 3 mods updated, 1 added", "You removed AppleSkin". Adds and on/off switches are record-only entries (undo reverses them, no file copies). Bulk changes are one grouped row. Person filter chips appear when more than one person shows.

## Review fixes (813c927)
1. **Real faces on desktop.** Row face = the same Minecraft head the Friends panel shows (`friends::face`). Order: the profile id saved on the record (`Who.mc`, so the face survives an unfriend) -> your active account for "You" -> mailbox friends / group members by id. Only with no face at all: a tinted initial tile (Sam in the shots). Web keeps letter tiles: face data doesn't reach hopperd.
2. **Desktop chips match the web.** `widgets::chip` (tinted, no border, no tick), chosen one in the primary tint, face inside each chip, 26px-class height like the web `.chip`. `toggle_chip_face` removed; `toggle_chip` back to what main has.
3. **"You" on a Hopper Server panel.** hopperd says "You" only while the owner is the only person on the panel (no users, no paired desktops). Once there are others:
   - owner actions -> "Owner"; panel users -> their name;
   - paired desktops -> their device name, which pairing already sets to "Hopper on <PC name>";
   - older entries with no name (made before anyone else was added) -> "Hopper Server", on the web and in the desktop's remote view.

## Files
- `crates/hopper-core/src/actor.rs`: who-scopes, Who (+ `mc` profile id, `with_face`), records, tags; tests.

- `crates/hopper-core/src/{recipe,sharecode,groupsync,modpack,undo,instances}.rs`: claim what a sync changes; undo stays quiet.

- `src/gpui/store.rs`, `store/friends.rs`, `addons_extra.rs`: friend scope (with face id) on follow apply; one batch for bulk/Update all/profile.
- `crates/hopperd/src/mods_*.rs`: `changer()` + `names_people()`, "Hopper Server" for unnamed entries once the panel has people, batch per request, undo by name across sets.
- `crates/hopperd/ui/src/ModBackups.svelte`: same rows + chips in the web UI.

## Notes for the maintainer
- **Web selected chip in light themes fails contrast: 2.80** (orange text on its 12% tint). It's the app-wide `.chip.on` / `.chip.acc` in `app.css`, not new here; desktop uses a darker ink and gets 4.55+. Follow-up: give the web an accent-ink colour for light themes.
- Group copies carry no profile id; the face comes from the group's member list when the person is in it.
- Known gaps: pack-update override configs carry no who; hopperd `mods_upload` and worlds installs aren't tagged; multi-person sets filter at set level.
- Web single rows put 6 px between name and verb (flex gap); group heads use a normal space (~4 px). Minor.
- Server owner is labelled "Owner" (auth has no owner name).
