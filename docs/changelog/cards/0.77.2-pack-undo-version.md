# Undo all on a pack update puts the pack's version and loader back

**Branch:** t3/pack-undo-restore-version   **Commit:** d9abcc46   **Size:** M
**Apps:** both. Desktop (instances) and Hopper Server (History undo for server packs had the same gap). One shared function in hopper-core does the work.

## From -> to
- Before: Undo all on "Updated pack X to 1.80.0" put back mods and configs, but the header still named the new version and the update was not offered again.
- After: Undo all also puts back the pack version, file id, loader version and Minecraft version. The header shows the old version and "Pack update" / "Update pack" return. The row then reads "Put back pack X to <old>".

## Notes for the maintainer
- Old marks (no `before`) still load; Undo all on those restores nothing extra (state Unknown, no toast).
- Undoing the "Put back pack" entry moves the pack forward again (tested).
- Conflict rule: compares the instance's current pack file id with the one the update wrote. If it differs, nothing is overwritten and a warning toast says the version stays.
- `store.rs` edit is small (records state before the update, marks after) to avoid clashing with the task-queue work.
- Rust `target` size not scanned (brief forbids `du`). Offer: `X:\Dev\tools\dev-clean.ps1` if disk is tight. Scratch data on rig `G:\rig-test\pack-undo-scratch` left in place.
