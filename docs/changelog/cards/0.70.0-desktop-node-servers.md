# Hopper desktop: servers on a Hopper Server's nodes show up and work

**Branch:** t3/panelled-node-servers-desktop   **Commit:** 021df659e6716c18ed65eb3197b0ae1c57896c6b   **Size:** M
**Apps:** both. Desktop and Hopper Server (the main panel's API). The web UI already had node groups. The backups change reaches the web UI through the same flag, with no web code changed.

## From -> to
- Before: a desktop paired with a main panel didn't list the servers on its nodes at all ("mainx Hopper Server · 0").
- After: each node gets its own group ("nodevm node · via mainx · 1"). Its servers show TPS and can be started, stopped, given commands, browsed, synced (mods and configs) and backed up, all through the main.

## Notes for the maintainer
- Route audit is in the agent report. All the desktop's GET routes relay fine with `:` as `%3A`. Two non-relayed routes are handled: `fs/fetch` (desktop skips it for node ids) and `logs/share` (desktop shares it itself). On the web, Share is hidden for node servers, so the two apps differ here.
- Not built: + (new server) on a node group (the desktop's host dialog doesn't send `?node=`), and the node's own online/stale light (the group uses the main's).
- Bug found that also happens on the main's own servers (not node-only): after pairing a pack on the Sync tab, Configs stays on skeleton rows until you leave the tab and come back (`rigsync::show` → `ConfigsPanel::show` runs before the pairing exists).
- The header History dialog stays empty after a desktop sync. Desktop sync history lives in Sync › History. Probably the same for a main's own server; not checked.
- The node panel reads `node.json` from its `--data` folder, not `home/.hopper-server`. A scratch node needed it copied there.
