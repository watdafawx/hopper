# Friends: keep a mod "Only on this PC", and a "Just for me" toast for locked mods

**Branch:** t3/friends-sync-local-only-mods (worktree t3-7e1367aa)   **Commit:** 1fa6782 (merged with main at 0.65.0)   **Size:** L
**Apps:** desktop only. Hopper Server has no friends sync, so it has nothing to change.

## From -> to
- Before: in a pack shared with friends (or a group copy kept both ways), every change went to everyone. There was no way to keep one mod different on your own PC, and a sync could turn a mod you had turned off back on.
- After: any mod can be marked "Only on this PC". Friends keep it the way it was, and sync, group merges and follow-triggered pack updates leave it alone here. Turning off or removing a LOCKED mod in a synced pack still happens at once for everyone (no dialog). It shows one toast for the whole batch, "Turned off Sodium Extra for Mia · [Just for me]". It names who the change reaches: one friend by name ("Mia"), several as a count ("3 friends"), a group by name ("drunk gamblers"). Just for me puts the mods back for everyone and keeps the change only on this PC.

- `crates/hopper-core/src/sharecode.rs`: publishing sends kept mods as friends had them; applying skips them.
- `crates/hopper-core/src/groupsync.rs`, `recipe.rs`: group merge and follows skip kept mods.

## Notes for the maintainer
- The toast does not autohide. The stock autohide is 5 s, and Just for me has no other way back, so it stays until closed. There is one per instance: a newer locked change joins the open toast instead of stacking a second one.
- The remove flow shows this toast instead of the usual "Removed X. Undo" toast when locked mods were removed. Undo is still in History, and the toast says so.
- Wording ("for Mia", "for 3 friends", "for drunk gamblers") was changed after review from "for Mia's pack". A pack you follow from Mia only gets a toast when the change goes back to her, which is a two-way group copy, so it names the group. The Friends row "Mia · 2 mods only on this PC" had no such problem and is unchanged.
- The batch and remove screenshots still show the old wording; only the single toast was retaken. The text comes from the same `for_whom`, covered by `a_change_names_who_it_went_to`.
- The blocking dialog from mock option A was replaced by this toast before the commit (your design change). Its screenshot is not in the card.
