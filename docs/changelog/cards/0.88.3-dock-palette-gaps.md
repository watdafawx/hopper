# Docks: palette keeps the side panel, "Not saved yet" no longer covers the close button, switching instance keeps unsaved edits

**Branch:** t3/dock-palette-unsaved-gaps   **Commit:** 31118eaf   **Size:** M
**Apps:** desktop only. Dock tenants (config panel, mod page beside a list, Friends) and the Ctrl+K palette do not exist in Hopper Server's web UI, so there is nothing to port.

## From -> to
1. Palette
   - Before: Ctrl+K, then a click anywhere (or Esc with a mod page open) also closed the right-hand panel.
   - After: while the palette is open, a click anywhere, or Esc, closes only the palette. Opening it keeps the panel. Same in Browse's mod page.
2. Not saved yet
   - Before: a toast for ~6 s covered the config panel's close X.
   - After: a strip inside the panel, at the bottom above the Save / Discard row, same words. The title, X and footer buttons stay where they were. It fades after ~6 s as the toast did.
3. Switch instance with unsaved config edits
   - Before: picking another instance silently dropped the edits.
   - After: refused, same strip shows, selection stays. Same for the palette ("open instance"), Friends "Show", back/forward, mod peek and the "go" links (all go through `LibraryView::select`, which returns `false` when refused).

## Item 1: which fix
Picked **(b), an app-wide flag** (`widgets::overlay_opened` / `overlay_closed`, a counter; `widgets::press_is_modal(window, cx)` = dialog or sheet or overlay). Why: making the palette a real gpui dialog would change its look, keyboard handling and focus; the flag is a small change, and one helper now serves Library's `dock_ignores_press` and Browse's `in_dialog`. A future overlay calls the two functions.
Two more pieces were needed, found on screen:
- The dock's release-dismiss now re-checks `press_is_modal` when it runs (deferred), because the title-bar "Ctrl K" button is a press outside the dock: the dock decided on release, before the palette existed. Side effect (good): a button that opens a dialog from the page no longer closes the dock first either (the old card listed that as a known gap).
- Esc: with a mod page open, focus can be on the page, so the palette's own Esc binding never fired and the app's `ClosePanel` closed the dock. `AppView::close_panel` now closes the palette first.

## Also checked: config panel hidden behind another tab
`refuse_unsaved` jumps to the Mods tab when the config panel is not shown (another tab is open), then flashes the strip. My read: fine and wanted. The refusal is explained where the panel is, and the user sees the unsaved edit instead of a notice about something off screen. Not changed.

## Notes for the maintainer
- `overlay_opened`/`overlay_closed` must be paired; `closed` saturates at 0 so a stray close can't lock docks open. Only the palette uses them today.
