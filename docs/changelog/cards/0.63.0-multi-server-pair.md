# One pack, several servers: pair, switch, sync all from the instance page

**Branch:** t3/instance-multi-server-pairing   **Commit:** 5ab10e9   **Size:** L
**Apps:** desktop only. Hopper Server's web UI has no instance pairing, so there is nothing to match there.

Mock: https://claude.ai/artifact/4b9H1JugtV4h9bojjyBLP9 (Now, A, B = pick, C). Pick and why: `picks.md`.

## From -> to
- Before: an instance could pair with one server. Pairing a second server from the Servers page silently made the instance show that one, and the instance page had no way to see both, switch, or unpair.
- After: the Server tab shows one underline tab per paired server (state dot + "In step" / "N differ" chip). Picking one switches the compare view and the header's server button. The row and the header ▾ menu have Pair another server, Sync to all servers… and Unpair. The play banner names the server that differs (the shown one first) and adds "X differs from this pack too." A pack with one server looks exactly as before (pixel diff 0). Its ▾ menu gains "Pair another server ▸" and "Unpair <name>".

## Notes for the maintainer
- Light-theme warning chips are 2.51:1 everywhere (`widgets::chip(theme.warning)` in addons, backups, configs, host dialog…). This is the palette's warning colour, not new here; left alone. It's worth one fix in the theme (a darker warning ink on light themes).
- At 960 px the sync list's "Server → Pack" column and the header title clip in the base build too (before-960-dark.png). Not new; left alone.
- Settings compatibility, both ways: old settings load unchanged (`shown_server` defaults to empty; tested). An older Hopper reading new settings sees `""` for an unpaired server. Its `paired()` returns early for any stored key, so it also treats that server as unpaired, with no name guess (checked in d7ea648). It ignores `shown_server` and shows whichever server it finds first.
