# A node's servers show their TPS and low-TPS alerts on the main panel

**Branch:** t3/node-server-tps-alerts-on-main   **Commit:** 24a86f5   **Size:** M
**Apps:** Hopper Server only (nodes are a Hopper Server feature; the desktop has no node view)

## From -> to
- Before: on a main panel, a node's server (dg on oracle) showed "TPS —" in its header and Live card, and the node's low-TPS banner never showed, because the main read alerts only from itself.
- After: the main asks each connected node for its alerts and shows them under the node server's id: the TPS chip (red when low), the Live card's "14.6 · 68.7 ms", the "dg is running slowly" banner, and the node's drive / memory alerts named after the node ("oracle: Drive C: is nearly full").

## Notes for the maintainer
- Dismiss: hidden on the main only (not sent to the node). On the node it would hide the alert for the node's own people too, and the main only ever reads alerts from the node (Look).
- dg twice on main's Overview: not a bug. The Overview grid lists every server the panel shows (its own and its nodes'), and the sidebar lists them too, the same as a local server shows in both. Found on the way, not fixed: a node server's RAM bar on the Overview card is drawn against the main's memory ("out of this PC's memory"), not the node's; the cards don't say which node a server is on.
- Light-theme red TPS chip (3.98:1) and Live TPS (4.39:1) are under 4.5:1 for every server; worth a colour fix separately.
- The scratch node started with `--data <pdata>` (moved into its home) didn't pick up `node.json` from `hopperd node join --data <home>\.hopper-server` until restarted; not looked into.
