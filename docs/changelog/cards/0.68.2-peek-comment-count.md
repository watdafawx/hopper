# Mod peek: Comments tab shows its count, loads ahead, and tags the mod's author

**Branch:** t3/peek-comments-tab-count   **Commit:** 5d74195   **Size:** S (plus the "Author" tag the user added)
**Apps:** both (desktop peek, Hopper Server mod peek + Browse page). CurseForge mods only: Modrinth and GitHub projects have no Comments tab.

## From -> to
- Before: Comments tab had no number (Files and Dependencies did); comments loaded only when you opened the tab; nothing marked the mod author's comments.
- After: tab reads "Comments 1357" once known (no number until then, never 0); the first page loads in the background when the peek opens; the mod author's comments and replies carry a tinted "Author" chip.

## How tested
- Tests: `cargo test -p hopper-core --lib`: 1263 passed, 0 failed, 60 ignored. New: `project_author_matched_by_id_then_by_name`, `reads_the_posters_id_and_login`. One earlier run failed `disk_watch::..._the_watcher_reports_an_install_once_it_settles_and_a_removal` (timing, builds were running in parallel); it passes alone and in the full re-run. `pnpm build` in `crates/hopperd/ui`: ok.
- On screen: desktop test build (`--mcp`, scratch HOPPER_DATA_DIR with `data\settings.json`, throwaway instance Scratch1, HOPPER_LOOPBACK=1, HOPPER_TEST_WINDOW=1) and a scratch hopperd (`--portable --data --home`, HOPPERD_SERVICE=hopperd-test) with a fixture via `HOPPER_TEST_COMMENTS`. Seen: no number before the page answers, "Comments 1357" after, instant tab on open, quiet failed prefetch then retry on tab open, Author chip on a pinned comment, a plain comment and a reply.
- Found and fixed on the way: web tab label stayed "Comments" in the sticky bar (store made its own `$state` inside the reader, so the reader never heard of updates). The store now reads without creating.
- NOT checked: the real CurseForge author-id match (only unit-tested; the fixture matches by name, and the real JEI author does not match the fixture author so no chip shows in the ModPeek shot); the shipped hopperd binary embeds the new UI only after a rebuild (checked through the proxy on `ui/dist`, not through an embedded build); Windows firewall n/a (loopback).
- Test data: fixture file + fake JEI mod in a scratch server; no real packs or servers; real `%APPDATA%\hopperd` untouched (scratch used `--data`).

## Notes for the maintainer
- Issues tab on another branch touches the same peek tab row: the label is `comments_label()` (desktop) and `commentsLabel()` (web), one line each in the tab bars, so a merge should be small.
- `cfcomments::authors(project)` does one `cf::get_mod` per project per session (cached) for hopperd, which has no project object in the comments route. Desktop reuses `m.authors` from the peek.
- Count is the endpoint's `pagination.totalCount`; I did not check whether it includes replies.
