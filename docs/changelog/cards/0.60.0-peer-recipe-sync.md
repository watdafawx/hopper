# Friends: pair from anywhere, follow a friend's instance, auto-update

**Branch:** peer-recipe-sync (worktree `.claude/worktrees/peer-recipe-sync`)   **Commit:** 2cd3f15   **Size:** L
**Apps:** desktop only. The Friends page has no Hopper Server web equivalent; the mailbox service is a separate Python service in `relay/`, deployed on the Oracle VM.

## From -> to
- Before: "Peers" showed addresses, ports and LAN discovery errors, and only worked when the two PCs could reach each other directly. File-by-file push/pull was the main action.
- After: "Friends" says what it does. Pair once with a code, share an instance as a recipe, and the other PC follows it: only the mod list travels, files download from their sources, and updates apply in place automatically. The direct list and file sync are under "On this network"; address/port live under Advanced.

## How tested
- Tests: `cargo test -p hopper-core --lib` 1089 passed, 0 failed; live mailbox test (register, invite, join, profile update, friends, publish, events) passed against the public tunnel.
- On screen: two isolated desktop clients; Invite → code; Join; Get this instance; follow status reached "Up to date"; MC profile update showed the real head and name. Direct desktop clicks were blocked by foreground focus, so the final button click-through used Windows UI Automation (`InvokePattern`/`ValuePattern`), not desktop control.
- NOT checked: a real mod download or a real pack update during an in-place sync (the live apply was a clean no-op); two physical PCs (both clients were on this machine, separate data dirs); the 960 px narrow window and light theme; the sync-off intro/empty card screenshots are not archived.
- Test data: throwaway `Recipe Test` instances, test mailbox accounts, a public test UUID (Notch) for the head; all removed. Production mailbox state reset.

## Notes for the maintainer
- Mailbox is live at `https://sync.kyuubi.dev` (Oracle VM, Cloudflare Tunnel, `hopper-mailbox.service`); OCI ports stay 22/51820.
- In-place sync requires the same pack version or the same plain game/loader; a newer file of the same pack is updated first. A different pack is refused (use Paste share code to create a new instance). Configs/worlds are not in a recipe.
- Hopper Server is unchanged; no server bump/release. The mailbox service is deployed separately from `relay/`.
- The local API token in `G:\Storage\cf-tunnel.token` has Tunnel + DNS edit; rotate/revoke it when no longer needed.
