# Appearance in the title bar: themes, zoom and two switches without opening Settings

**Branch:** worktree-appearance-popover (worktree `.claude/worktrees/appearance-popover`, main merged in)   **Commit:** 1f3dff1 (4 commits + merge)   **Size:** M
**Apps:** both. Zoom, Still header, Smooth scrolling and "Yours" are desktop only (the web UI has no such settings; see Notes).
(Card written in the worktree because a hook blocked the main-checkout path; screenshots are in both `X:\Dev\hopper\.claude\changes\appearance-popover\` and next to this card.)

## From -> to
- Before: changing the theme, zoom, Still header or Smooth scrolling meant Settings > Appearance (Hopper Server's web UI had no theme choice at all).
- After: a palette button beside the gear (Ctrl+Shift+A) opens a popover: themes in blocks (Follow Windows, Dark, Light, Yours), Zoom stepper, the two switches, theme folder and reload, and a link to Settings. Resting on a theme for 150 ms shows it on the whole app; a click keeps it; leaving the list, Esc or a click outside puts the saved theme back. Option B of the mock.

## Notes for the maintainer
- Differences, plainly: web has no Zoom (browser zoom), Still header, Smooth scrolling, theme folder, reload or "Yours" (it has no folder of user themes); web wording is "Follow system" (desktop: "Follow Windows"); the web choice is per browser (localStorage), desktop's is in settings; web recolours through CSS variables, so a few hard-coded colours in app.css do not follow a theme (hero tints, some outlines); the web popover has no animation.
- Single source: desktop `PALETTES` is the truth; `themes.json` is generated and a test fails if they differ. Adding a theme = edit theme.rs, run `UPDATE_THEMES=1 cargo test web_theme_file`.
- The existing Switch and Button::link components fail contrast on some light themes (switch track vs thumb 2.67 on Rose Pine Dawn; link text 2.67). I avoided the link in the new popover (ghost button) but did not touch the shared widgets.
- Bug (existing): title-bar bug icon sits 2 px low versus its neighbours on desktop.
- Web title bar: the Ctrl K hint and host name now hide under 900 px (they hid under 760 px before); under 760 px the bar still scrolls sideways as before.
- Desktop window minimum is 960 px, so "900 px" in the brief was tested at 960.
- The `mcp__hopper__*` tools in my session talk to the user's own Hopper; I used `state` once, read-only, before switching to curl on my scratch port. My first scratch launch lacked instance roots in settings and listed real instances; killed within seconds, nothing was changed.
- Disk: shared target is `X:\Dev\hopper\target\perf*`; I did not check its size. Not pushed, not merged into main, no version bump.
