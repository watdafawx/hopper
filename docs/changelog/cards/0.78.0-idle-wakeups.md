# Hopper sleeps when idle: timers run only while their feature is in use

**Branch:** t3/idle-timers-cleanup   **Commit:** d5754abd (baseline counter commit c8843119)   **Size:** S-M
**Apps:** desktop only (the timers are in the desktop app; Hopper Server has no equivalent loops)

## From -> to
- Before: with nothing happening, Hopper woke ~33x/s for MCP, every 3 s for the Downloads folder, every 5 s for the panel poll, every 3 s for the History badge, and loaded Browse's Minecraft version list at startup.
- After: each timer runs only while its feature is in use and starts the moment the feature turns on. History badge updates from store events. Version list loads on first Browse open. No UI change.

## Wake-ups (rig, debug build, scratch data, nothing open; counted by `HOPPER_MEMLOG=1`, new "wakes" section in `memlog.txt`)
| Timer | Before | After |
|---|---|---|
| MCP loop (30 ms) | ~490 per 15 s (32.7/s) | 0 with MCP off; ~490 per 15 s only while MCP is on |
| Downloads watch (3 s) | 5 per 15 s | 0 |
| Panel poll (5 s) | 3 per 15 s | 0 with no panel; ~3 per 15 s with a paired panel |
| History badge (3 s) | 5 per 15 s | 3 in the first minute, then 0 at idle |
| Browse version list | 1 at start | 0 until Browse is opened (then 1) |
| store message poll (50 ms) | ~296 per 15 s (19.7/s) | unchanged (not in scope, see notes) |
