# Undo works for mods only the CurseForge website hands out

**Branch:** t3/06ff6231   **Commit:** b8f35086   **Size:** M
**Apps:** desktop + Hopper Server (shared hopper-core fix; the server panel only shows a message, see notes)

## From -> to
- Before: updating or removing a mod whose author turned off third-party downloads (Structory: Towers) deleted its jar from History. Undo then failed with "downloading X again from CurseForge: X can only be downloaded from the CurseForge website".
- After: History keeps the real jar for such files, so Undo just works. Entries already slimmed to a note: Undo opens the download window for the file (same install as the mod page's "Roll back to"), and adds it when it arrives.

## Cause
`sync::backup` -> `backups::note_instead` wrote the note and deleted the jar for every jar the instance knows, with no check that the site still hands the file out. The check (`backups::hooks().0`, which includes `cf::download_url`) only ran for the "Free up space" path.
