# Mod peek: tabs never clip or wrap in a narrow panel

**Branch:** t3/1417f0ac   **Commit:** a1a796065bf86ddae7296d3bf060aefd880850c9   **Size:** S
**Apps:** both (desktop clipped the last tab; Hopper Server wrapped the tabs onto a second line)

## From -> to
- Before: at the narrowest peek width (26 rem) "Issues" ran to the panel's right edge and was clipped (page row and compact bar). On Hopper Server the same row wrapped to two lines below ~560 px.
- After: one line at any width. Desktop: full labels while they fit, then icons (open tab keeps its label, others get a tooltip), then the kit's overflow menu. Server: full, then no counts, then icons.

### Found in the real UI (the static harness could not show these) and fixed (commit "Web peek tabs: space before the counts, tighter row under 230 px")
1. **Counts glued to labels at 521 px and wider**: "Versions58", "Dependencies0", "Gallery6", "Comments0". Svelte trims the space at the start of `<span class="tn"> {n}</span>`. Fix: `.tn::before { content: '\00a0' }`. Before: gap between label and count 0 px at 1400 / 640 / 700 (pixel check: no empty column run at the count). After: the gap is there in all 24 full-width shots.
2. **260 px panel: last icon cut off**. Row 194 px, content 201 px (`scrollWidth`), last tab 7.3 px past the edge, row scrolled. Fix: `@container (max-width: 230px)` tightens the margin 10 > 6 px and icon padding 4 > 3 px. After: row 194, last tab right edge 16.7 px inside (open tab Description); worst case, Dependencies open: last right edge 1333 vs row edge 1334 (**1 px to spare**).

### Results after the fix (all 58 captures pass; row = the `.tabs` box)
Pass criteria per shot: one band of buttons (no wrap), no scroll (`scrollWidth` = `clientWidth`), last tab right edge <= row edge, no two tabs overlap (min gap), underline under its own label (pixel columns of the orange line vs the label's rect, <= 1.5 px), icon-only tabs are `<button>` with `aria-label` and `title`, label contrast >= 4.5:1, icon contrast >= 3:1 (sampled pixels, WCAG ratio, not the tokens), counts separated from the label by a gap.

### Not fixed, found on the side (pre-existing, not tab-row)
- **The compact bar never appears in a side peek.** In the peek the panel only scrolls 98 px (content 926 in 828) and the observer in `BrowsePack` (`stuck = !isIntersecting && boundingClientRect.top < rootBounds.top`) compares against the window top, but the panel's top is 304 px down (>= 42 px even when pinned), so it never counts as "scrolled past". So the compact bar tab row could only be measured on the Browse page, where the page scrolls (jumped to the end with `scrollTop = max`; with the mouse wheel it engages at 1400 px but not at a 296 px window, where the header above the page is 219 px tall). Same snippet and CSS in both rows.
- At the 260 px panel the "Open on CurseForge" button above the tabs looks tight against the panel's right edge (not measured).
