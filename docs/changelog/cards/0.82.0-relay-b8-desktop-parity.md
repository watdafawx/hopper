- On screen: desktop debug build on rig slot 1 (MCP 47835), paired to a scratch hopperd (8811) with a scratch relay (rig loopback, state "up", servers survival + creative). Saw: card up and after Test again (failed because the fake address doesn't resolve, rows shown); relay list with both servers; a paired PC that may not manage sees the caption; granted manage, list and gear appear; Take off asked first and really took creative off (checked in `/vps-relays`); setup stages 1 and 2 in all three sign-in modes; Connect against an unreachable host showed the panel's error; light and dark; narrow window.
- NOT checked: setup steps 3 to 5 (Check, Install, Test) and the Remove / Forget confirms: no VPS or ssh target was allowed. The voice row (no voice mod in the scratch). The stale-address note + Repair on screen (covered by a unit test only). A side panel open next to the card. Test again's "running" state (finished too fast to catch).
- Test data: scratch hopperd + relay in `E:\scratch\relay-b8` on rig; no real instance, server or panel touched. Processes stopped; the folder is still there.

## Notes for the maintainer
- Wording differs from the web in: "this panel" is "Hopper Server" in setup and the list; "since HH:MM" in the header is "Up · 3 h" in the health row; Cache hits replaced the old Players tile; the Private key box says "Paste the key (-----BEGIN …) or choose a file" (the web's longer hint clipped in GPUI's one-line placeholder).
- Not ported: sparkline; Use / Stop using / Play at home (card points to Hopper Server).
- Found while testing: whether this PC may manage is read when a server page opens, so granting "manage" in the panel needs the page reopened. Left as is.
- A paired PC without "manage" rights sees no setup, no Test again and the caption in Settings, same as the web routes refusing it.
