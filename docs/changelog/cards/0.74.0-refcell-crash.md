# Test screenshots no longer break a frame ("RefCell already borrowed")

**Branch:** t3/ad97f357   **Commit:** e4d33e6   **Size:** S
**Apps:** desktop only (Hopper Server has no GPUI window)

## From -> to
- Before: every MCP `screenshot` logged 2-4 `ERROR RefCell already borrowed` lines (no file named) and dropped that frame. Reported as "RefCell errors on Browse clicks"; it was the screenshot after each click.
- After: screenshots are taken between GPUI updates; 0 such lines in 7 hammer rounds. Log lines from GPUI's `log_err` now name file:line instead of nothing.

## Cause (call chain)
```
hopper mcp::start loop -> cx.update(|window, cx| input(Screenshot, ..))   <- App RefCell borrowed
  -> mcp::capture -> PrintWindow (NtUserPrintWindow)
    -> Windows sends WM_PAINT synchronously (KiUserCallbackDispatcher -> CallWindowProcW)
      -> gpui-pre-windows handle_paint_msg -> on_request_frame callback
        -> handle.update(&mut async_cx, ..)  -> try_borrow_mut fails
          -> .log_err(): "RefCell already borrowed"
             gpui-pre-0.3.9/src/window.rs:1811 (thermal_state), :1918 (schedule_frame),
             :1842 and :1874 (draw/present) — frame skipped, no panic
```
Backtrace (debug build, HOPPER_BORROW_TRACE hack, since removed): 326/326 error lines had `NtUserPrintWindow` on the stack. See `before-hopper.log`.

Not a panic: no `panic at` line, no `crash.log`, no Windows Application Error for hopper.exe on rig in 7 days.
"App quit twice": no evidence of a crash. My own run from push-to-rig slot 1 also vanished silently mid-session; `push-to-rig.ps1 -Stop` without `-Slot` kills apps in all 3 slots, so another session's `-Stop` is the likely cause. Running from a private scratch copy, the app stayed up through 14 hammer rounds.
