# Changes in the files: what changed in a mod version when its author wrote no changelog

**Branch:** claude/files-changes   **Commit:** 4601f22 (6 commits, `793c85b`..`4601f22`)   **Size:** M-L (first slice only)
**Apps:** both (desktop + Hopper Server). Not applicable: desktop for *remote* panel servers (see Notes).

## From -> to
- Before: a mod version with no changelog showed "No changelog for this version."
- After: opt in. Off (default): the first such card shows "The author didn't write a changelog. Hopper can compare the files to show what changed." with **Turn on** and **Not now**. On: the card shows "No changelog from the author. What changed in the files:", the list, and "Scanned from the jar files by Hopper, not by the author." Same words in both apps (the text comes from `hopper-core`).

## What the scan lists (all in `crates/hopper-core/src/jar_changes.rs`)
New/removed blocks and items (names from `lang/en_us.json`), new/removed config options (only an option name directly after its shipped description in a config class's string table), languages added/removed, version / Minecraft / loader range / dependency changes, data files (recipes, loot tables, tags, advancements) compared by meaning (`conditions` -> `neoforge:conditions` and `forge:` -> `neoforge:` condition types = "rewritten for a newer format, no gameplay change"), textures/models counts, "Only the mod's code changed. The author hasn't written what.", "The files have the same content. Only the version details changed.". No class counts, no intent, no decompiling. Entries compared by the zip index's CRC-32 + size (stored vs compressed jars are equal). Bounds: 50,000 entries, 4 MB per read file, 96 MB read per jar, unsafe names skipped.

Real jars (Modrinth, downloaded to my scratch folder, deleted after): Iron Furnaces 4.3.1 -> 4.3.2 = code only + "6 data files rewritten for a newer format"; Spelunker's Charm II 5.0.6 -> 5.1.0 = 8 new blocks, 19 new config options with the author's descriptions, 2 languages, 8 loot tables, textures; Pipez 1.2.19 -> 1.2.31 = 3 Spanish languages, 10 translations updated, 1 English text removed. (Research note found about 22 options; this reads 19 because it only claims name + description pairs.) Explorify was only built as a fixture.

## Notes for the maintainer
- Decisions: the notice shows once per list, on the first version with no changelog (the others say "No changelog for this version."), so four cards don't all repeat the same offer. At most 5 versions per opened list are compared (`MAX_PER_VIEW`). **Not now** hides the notice for that mod: desktop keeps it in `dismissed_notices` (`files-changes:<project>`), the web UI in that browser's localStorage. The oldest version Hopper knows of just says "No changelog for this version."
- The setting lives in desktop Settings › Content (next to the GitHub options) and in the panel's "Mod sources" page; the one-line help is `SETTING_HELP`. It is the panel's own setting, owner only to change; any signed-in user sees the result.
- Reuse of local files: the installed jar and files History kept with the same name (checksum or size checked), else one download per missing side through `cf::download_url` + `download_checked` (existing retry/limits). A file from GitHub or a link is only compared when both files are on this PC. Jars live in `<temp>\changelog-scan\<pid>-<n>\` and are deleted when the scan ends; the folder is also cleared at start (desktop and panel) and at desktop quit. Results: `<cache>\changelog-files\<sha1 of project|old|new>.json`, 90 days. History and backups are untouched; no automatic backups.
- **Desktop for remote panel servers:** desktop has no path today that shows a remote Hopper Server's mod versions/changelogs (nothing calls the panel's `mods/changelogs`), so there was nothing to point at the new route. Not done; the route is ready if that screen is added.
- Not in this slice: pack zips (`.zip`) are never scanned (packs keep the old text), jar-in-jar, the pack-format number to Minecraft version table (the line only says "Supported pack format changed"), non-English language text, the mod peek FileLog's "first version" lookup uses the file's own Minecraft version and loader tags.
- Follow-up worth a look: the `hopper-gpui-testing` fixture trick (a fake `install::changelogs`) would be handy as a real dev-only hook.
- Worktree `.claude/worktrees/files-changes` still holds git-ignored `crates/hopperd/ui/node_modules` and `dist`; it shares `target/perf3`.
