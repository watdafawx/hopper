# Deleted instances, worlds, backups and servers wait in Recently deleted for a week

**Branch:** t3/recently-deleted-undo-deletes   **Commit:** 3860352a (merge of main at a5fa1689)   **Size:** M
**Apps:** both (desktop gets Recently deleted; Hopper Server already had it for servers, now on the same shared code, with the same wording)

## From -> to
- Before: deleting an instance, world or backup sent it to the Recycle Bin (copied to C: when it was on another drive) or deleted it for good with the "Skip Recycle Bin" setting on; nothing in Hopper could bring it back.
- After: a delete moves the folder into `.hopper-deleted` on the same drive (a rename, no copy). It stays 7 days (Hopper Server: 30), then a background sweep deletes it. Settings › Library & folders lists it with Restore, a trash button and "Empty now". Every delete dialog has a "Delete for good now (can't be undone)" tick box that changes the button to "Delete for good". The "Skip Recycle Bin" setting is gone.

## Follow-ups (2026-11-16, branch t3/recently-deleted-follow-ups)
Rule now: anything the player deletes by hand goes to Recently deleted (same drive, 7 days; Hopper Server: its trash, 30 days). Automatic clean-up (History retention, cache trimming) deletes for good. The `trash` crate (Recycle Bin) is gone from the workspace.

Call sites changed:
1. `retention.rs` clean_up / preview / check / schedule: Recycle Bin -> for good (both apps; Hopper Server's disposer no longer used for retention).
2. `src/gpui/content.rs` Screenshots grid delete + viewer delete: Recycle Bin -> Recently deleted (kind Screenshot).
3. `install.rs` `delete_path` (install::delete, delete_loose_file, `locked::flush` queue): Recycle Bin -> Recently deleted (kind File).
4. `crashfiles.rs` log delete / clear: Recycle Bin -> Recently deleted (kind Log) on desktop; server trash on Hopper Server.
5. `hosting/backup.rs` delete (Hopper Server snapshots): for good -> Files › Trash (30 days); prune stays for good; `gc` keeps chunks of trashed manifests.
6. Removed dead code: `backups::delete`, `instance_ops::move_to_hopper_trash`.

Also: instance groups / datapack dest / pack-update clean / pairings ride along in the deleted item's meta and come back on Restore (dropped with the item when swept or emptied); a failed instance delete re-watches its folders (`DiskWatch::reclaim`). "Keep the last" text: "older ones are deleted for good".
