# A paired panel that freezes now shows as down in the server list

**Branch:** t3/52766b3c   **Commit:** see report (committed on this branch)   **Size:** S
**Apps:** Hopper Server web UI only. Hopper desktop does not have this hole (see Notes).

## From -> to
- Before: a paired panel whose process hung (or whose network dropped without a word) stayed green with its servers listed, for as long as you looked (64 s and 72 s in two runs). The page waited for the browser to say the live socket closed, and with a frozen peer that never comes.
- After: the page notices the panel went quiet. 9 s after the freeze the group says "Can't reach <panel> · Reconnecting…" (amber dot, servers dimmed "Seen just now"), at 24 s it turns "Offline" (red dot), and when the panel is unfrozen it is back to green by itself (10.5 s and 16.7 s in two runs). This is the same path a cleanly stopped panel already took.

How: each live socket gets a watchdog (`lib/socketWatch.js`, wired in `openSocket` in `lib/panels.svelte.js`). The panel sends its servers every second, so 10 s of silence on an open socket, or no "open" within 5 s (`LIST_TIMEOUT`) of creating it, means the panel is gone. The page drops that socket itself (handlers detached, `close()`), then runs the existing `down()` + `later()`. The watchdog is cleared on close, on replace, and wherever a panel's runtime stops (turned off, removed, signed out, reload of the list) via one new `detach()`.
