# Browse: Down arrow keeps going through pages of results

**Branch:** worktree-browse-arrow-paging   **Commit:** tip of that branch   **Size:** S
**Apps:** desktop only. Hopper Server's web Browse has no arrow-key list navigation, so nothing to port.

## From -> to
- Before: Down at the last loaded row could stall when the next page held rows already listed (same page asked again forever).
- After: the next page starts after what the server has handed over; Down keeps asking until a new row exists, then picks it.

## How tested
- Tests: `key_move_walks_through_pages_of_repeats`, `reload_for_key_stops_at_the_end` pass (65 in the changed bin).
- On screen: scratch build, Modrinth, throwaway settings. Down walked 160+ rows (4+ page loads) at 150-200 ms and with no delay; Up x20 after. The old build did the same up to ~200 rows.
- NOT checked: **could not reproduce the stall on Modrinth**, before or after. The fix targets the cause found by reading (offset = `results.len()`; an all-repeat page re-asks the same offset). CurseForge not run (no key). Held-key repeat from a real keyboard not tested (MCP key only).
- Old build, Mods tab, ~32 no-delay Down presses once aborted the process (0xc0000409, no stderr). Not reproduced on the new build (120 presses) nor at 250 ms spacing; cause unknown, may be MCP-injection flakiness. Worth a look if seen again.
- Test data: scratch data dir with `browse_modrinth`; no instances.

## Notes for the maintainer
