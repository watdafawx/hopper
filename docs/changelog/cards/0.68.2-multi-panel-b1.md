# Hopper Server: sign in and work from another panel's page (multi-panel B1)

**Branch:** t3/multi-panel-b1-cross-origin-auth   **Commit:** 070391e   **Size:** M
**Apps:** Hopper Server only (server side of multi-panel; no UI yet, B2 builds the UI that uses it)

## From -> to
- Before: a panel's web UI could only talk to its own panel; other origins got CORS headers (B0) but no way to sign in, open live updates or download files.
- After: a page whose address is listed in a panel's Settings › Access & devices can sign in with a bearer session bound to that page, open the live WebSocket with a one-use ticket, and download files through one-use links. Unlisted pages get nothing usable.

## Files
- `crates/hopperd/src/grants.rs`: new one-use tickets and file links
- `crates/hopperd/src/auth.rs`: origin-bound sessions, list, revoke
- `crates/hopperd/src/api.rs`: bearer login, ticket, sessions routes
- `crates/hopperd/src/fs_api.rs`: file link issue and redeem
- `crates/hopperd/src/security.rs`: remote session counts as other page
- `crates/hopperd/src/web_access.rs`: removing page ends its sessions
- `crates/hopperd/src/cross_origin_tests.rs`: 16 end-to-end refusal tests
- `design/multi-panel.md`: "B1 as built", choices, threat list

## How tested
- Tests: `cargo test -p hopperd`: 166 passed, 0 failed, 3 ignored (includes 16 cross_origin_tests + 4 grants tests).
- On screen: two scratch panels on loopback (ports 18791/18792, own --data/--home). From panel A's page: hello, readable 401 and 403 bodies, bearer sign-in, ws ticket + WebSocket snapshot, ticket reuse refused, file link download, link reuse refused, path outside server refused. From localhost:18791 (unlisted): fetch blocked, sign-in 403 without CORS header, WebSocket refused.
- NOT checked: TLS/https origins in a browser (tests cover the rule); a real second machine; zip links in a browser (tested in unit tests only).
- Test data: scratch panels in the session scratchpad, stopped after; %APPDATA%\hopperd\data untouched (last write Oct 30).

## Notes for the maintainer
- Added session list + sign-out routes (design assumed they existed). No UI for them yet.
- A session from another page can't manage users/devices/tokens/2FA/page list even if Host is faked.
- Desktop app not touched (nothing to do there for B1).
