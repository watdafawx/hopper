# Server History opens fast; truer "your mods" line; honest pack update toasts

**Branch:** t3/b6bbc0bc   **Commit:** 00c4bcf   **Size:** M
**Apps:** Hopper Server (History speed, toast) + desktop (pack update window line, toast for a server's pack update, Backups view sizes). Same History route serves both.

## From -> to
- Before: History on a server took ~2.5 s to open (scratch: 386 entries in 980 folders). The pack update window said "Nothing of yours in the pack's folders" even with a hand-added jar in mods/. Server pack update toasts always said "updated to".
- After: History opens in ~0.44 s the first time, ~0.23 s after that. A jar dropped into mods/ by hand counts as "N mods you added". Server pack toasts say "reinstalled at" (same version), "rolled back to" (older) or "updated to", like instance toasts.

## What changed (and why)
- Listing the folders is waiting on the disk, not work: one folder per action, a handful of tiny reads each. Folders are now read side by side (`configindex::par_map`) in `backups::list`, `history` (records), `jar_copies`, and `retention::scan` (sizing).
- `retention::usage` and `preview` each did the same scan: `usage_and_preview` does it once (desktop's Backups view uses it too).
- The route runs the three listings together, and keeps the sizes (folder usage, Clean up preview, full-copy bytes) per server while the backups folder lists the same entries (top-level count + mtime), the Clean up rules are the same, and for at most 5 minutes. Undo / put back / restore / delete / Clean up / Free up space drop them. The entries themselves are read fresh every time.
- Folder entries use the listing's own file type instead of a stat per entry.

## Wording (item 2)
- The line is `plan.your_mods` + `plan.your_files`. `your_mods` was only the instance's recorded mods not from the pack; a jar the player dropped into mods/ has no record, and `mods` is in `NOT_LISTED` for files, so it was counted nowhere. Now jars in mods/ that no record or pack change names count (turned-off ones too).
- Text is now "Nothing of yours in the mods folder or the pack's folders" (says what it checked). Hopper Server's pack update says "Nothing of the server's own in the pack's folders" and already counts the server's mods folder from disk: left as is.
- Resource pack / shader pack jars dropped in by hand are still not counted (their folders aren't the pack's and aren't mods).

## Toast (item 3)
- `hopper_core::jobs::pack_done_title(name, shown, was, now)`: same file -> "reinstalled at", lower file id -> "rolled back to", else "updated to"; unknown `was` (0) reads as an update. Used by the instance update, the desktop's server pack update (including a paired Hopper Server), and Hopper Server's web toast (`headline` in the job result).
- `was` for a server = the server pack file in its `.hopper-server-pack.json` record. A server with no record says "updated to" (it can't tell).
