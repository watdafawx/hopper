# Bookmarked mods open the same full peek as search results

**Branch:** claude/bookmark-peek-939138   **Commit:** see `git log` on the branch (one commit)   **Size:** S
**Apps:** desktop only. Hopper Server has no bookmarks (no bookmark code in `crates/hopperd` or its web UI), so no such gap there.

## Root cause
A bookmark keeps only name, icon, author, summary, page, downloads. `Bookmark::to_mod()` builds a bare `cf::Mod` from it and `open_detail` showed that as is. Dates, categories, game versions, loaders, side, license and the screenshot strip all come from the full project record, which was never asked for (only description + gallery were).

## From -> to
- Before: peek from Bookmarked shows title, author, downloads, link, tabs only.
- After: peek opens at once with the saved fields, then the full project is looked up (`source::get_mod`, CurseForge or Modrinth) and the same peek fills in. Lookup failed (offline, project gone): saved fields stay, no new error. A successful lookup also refreshes the saved bookmark (downloads, author, icon...) so the list stays current.
- Applies to any other short record opened in the peek (`bookmarks::is_slim`), not only bookmarks.
