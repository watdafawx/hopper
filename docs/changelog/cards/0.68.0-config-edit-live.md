# Config editor: typing counts as a change right away

**Branch:** t3/config-editor-live-edit   **Commit:** 0c832f8   **Size:** S
**Apps:** both (desktop config editor + Hopper Server web config editor have the same bug)

## From -> to
- Before: typing in a text/number field changed nothing until you left it. Footer stayed "No unsaved changes", Save stayed off. Clicking empty space didn't leave the field.
- After: every valid keystroke updates the setting; footer count and Save follow at once. Bad value shows its reason under the field and keeps the last good value. Click outside lets go of the field. Enter commits. Escape (desktop) puts the setting back to what it was when the field opened.

## Measurements
No layout change (no new boxes or sizes), so no pixel claims. Behaviour claims (footer text, Save enabled, field unfocused) were read from the screenshots above, not measured numerically.
- NOT measured: error text position/contrast under the field (it reuses the existing error style).

## Files
- `src/gpui/config_view.rs`: live edit, click-away, Escape revert, Text tab sync
- `crates/hopperd/ui/src/lib/ConfigRow.svelte`: oninput for number/text/colour fields
- `crates/hopperd/ui/src/lib/configs.svelte.js`: partial colour is invalid, not applied

## How tested
- Tests: `cargo test -p hopper-core --lib` 1241 pass, 1 fail: `crashdetect::tests::a_mixin_into_an_updated_mod_names_the_update` ("yesterday" vs "today", clock-dependent, from main commit 36886eb; hopper-core untouched).
- `pnpm build` in `crates/hopperd/ui`: builds clean (only the usual chunk-size warning).
- On screen: desktop test build via `--mcp`, throwaway instance CfgTest with a copied config file: typed in URL / name / number (valid, out of range) / colour, clicked empty space, Enter, Escape, Text tab. Web: scratch hopperd + real Chrome, same fields.
- NOT checked: list-item add field (not live by design: item is not a value until added); Escape in web (existing handler left as is).
- Test data: scratch data dir, loopback, test window; scratch hopperd with `--data`. No hacks to revert.

- Accidentally launched the real `hopper.exe --version` once (opened a second instance); killed by PID, real Hopper untouched.
- Web Text view (Files-style editor) is a separate editor, not changed.
