# Sync: a mod turned off on the server but on in the pack now shows as out of sync

**Branch:** t3/sync-enabled-state-diff   **Commit:** 413364a   **Size:** L
**Apps:** both (shared sync code in hopper-core, desktop Sync tab + banner, Hopper Server gets a new records route; web UI itself unchanged)

## Root cause (the player's report: Mekanism Magic on in TNP LL8, still off on TNP-LL8, Hopper said in step)
1. **No out-of-sync.** `rigsync::diff_mods` filed "same file, on in the pack, off on the server" as a Skip ("Kept off"). `join_check` skipped every row whose server copy was off, so the play banner never fired. On a version swap, `sync::plan` always kept the new file off, so updating 5 mods while some were off left them off on the server even after the player turned one back on.
2. **Identity lost.** A sync copies jars but never carried their CurseForge/Modrinth record. Jars a sync turned off on a remote Hopper Server go through `/mods/toggle`; for a jar the panel doesn't know, `index_of` makes a bare entry (project 0, name = file name). Identify treated bare entries as known (`loose_jars`), so they stayed "Add a source to get updates" forever, and counted in "N jars not from CurseForge".

## From -> to
- Before: Mod on in the instance, off on the server: no banner, Sync tab "Nothing to sync", row sits under "Kept off"; server shows the jar by file name with no source.
- After: Banner "On here, turned off on the server: Mekanism Magic"; Sync tab "Turned off on the server" group with "Turn on on server"; after sync the server has it on and named. Bare entries get named by the sync (or by Identify).
