# NeoForge/Forge packs made on Windows now start on Linux and macOS

**Branch:** t3/15987177   **Commit:** see git log (branch t3/15987177)   **Size:** S
**Apps:** both (shared hopper-core: Hopper Server and desktop go through `script::launch_command`/`read_launch`)

## From -> to
- Before: Linux start ran `java ... @libraries/net/neoforged/neoforge/21.1.265/win_args.txt nogui` -> `Could not find or load main class cpw.mods.bootstraplauncher.BootstrapLauncher` (win_args uses `;` classpath separators).
- After: same pack on Linux/macOS runs `java ... @libraries/net/neoforged/neoforge/21.1.265/unix_args.txt nogui`. On Windows a pack naming unix_args.txt gets win_args.txt. If the sibling file is missing, the named file is used as before.

## Notes for the maintainer
- Swap happens when the launch command is read, not in run.bat: run.bat/start.bat stay as written, so they still work on Windows and Hopper's own run.bat regeneration (`run_bat`, create.rs, server_update) can keep writing win_args without switching it back.
- Not changed: run.sh/start.sh preference. They vary per pack (some need interactive prompts or `sudo`), and parsing them would be a second parser; the args swap fixes the failure with one small pure function.
- Forge's `forge_target` / NeoForge install still name win_args in run.bat (it is a .bat); read-time swap covers them.
