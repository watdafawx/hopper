# Check for updates now sees a GitHub release made minutes ago

**Branch:** t3/48f47982   **Commit:** e61e0c2d   **Size:** S
**Apps:** desktop + Hopper Server (same fix both sides)

## From -> to
- Before: pressing "Check for updates" within 10 min of the last look used Hopper's saved GitHub release list without asking GitHub, so a new release (mc-mcp v0.2.0) showed "Up to date".
- After: a check the player starts always asks GitHub (with the saved ETag; unchanged = free 304, not counted in the 60/h limit). Start-up and background checks still use the 10 min window.
- Paused by GitHub's limit: the saved answer stands in and the Mods tab says "GitHub is limiting checks for now. Mods from GitHub are checked again at HH:MM." instead of "Up to date" (panel: same text as the toast). Before it said nothing (or a red error when nothing was saved).

## What asks GitHub now (Check::Manual)
- Mods tab check button, palette "Check for updates", and any forced re-check (after Undo, trusting a source, unlocking, re-identify).
- Versions / changelog dialog (`install::changelogs`), a mod's page file list in Browse.
- Pasted link (`resolve`), adopting a jar (`plan_adopt`).
- Hopper Server: check button (`/mods/updates?force=1`), its Versions list.
- Still Auto: start-up and 30 min checks, pinned installs, mod page text, dependency lists.
