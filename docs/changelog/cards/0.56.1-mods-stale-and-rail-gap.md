# Server Mods tab: list and counts follow the panel; Updates icon no longer leaves a gap

**Branch:** claude/mods-stale-rail-gap   **Commit:** 15c519f   **Size:** M
**Apps:** both (BUG A fix is in Hopper Server's list route + desktop; BUG B is desktop only: the web rail already sizes by digits)

## From -> to
- Before: a server on a Hopper Server showed its mods as the panel's old `hopper.json` said: jars swapped on disk (a sync, SFTP, a job) stayed listed under their old file with the old update offer ("Update all (16)", "All 1012"), and untracked jars weren't in "All". With 2+ digit update counts the Updates icon left a gap of ~94 px before the next icon.
- After: the list drops entries whose jar is gone (as the web table does), pulls the panel's update offers again when the set of jars changes, and "All" counts the panel's untracked jars. The Updates icon is as wide as icon + badge + 8 px at 1 to 4 digits.

## Root causes
- A: `GET /servers/{id}/mods/instance` (desktop's list) returned raw `hopper.json` entries, including ones whose jar no longer exists; the web table filters those. Desktop's update offers (kept up to 30 min) matched the old file names, so they stayed. Reproduced on a scratch panel: after renaming `alpha-1.0.jar` -> `alpha-1.1.jar` on disk the route still listed `alpha-1.0.jar` (+ `alpha-1.1.jar` as loose).
- A2: desktop "All" = tracked + `loose_jars(inst)`, which reads the local disk (nothing for a panel stand-in root): the panel's loose jars were left out.
- B: `rail_badge_extra(count, ..)` took the count VALUE as the number of digits (16 -> a 16-digit badge ~ 94 px of extra right padding). Introduced with the 0.55.0 badge rework.
