# Hopper saves its own log, with buttons to open or copy it

**Branch:** t3/09470e0f   **Commit:** dbe0025   **Size:** M
**Apps:** desktop (Hopper Server already keeps `hopperd.log`; see Notes)

## From -> to
- Before: Hopper's own log went to stderr only. The installed exe has no console, so a player had nothing to send with a bug report.
- After: every run writes `logs\hopper.log` in Hopper's data folder (the same place as `sessions`; follows `HOPPER_DATA_DIR`). Settings > Advanced has a "Hopper's log" row with **Open logs folder** and **Copy log**.

## How the log works
- Place: `<data folder>\logs\hopper.log`. Rotated at the start of the real app run: `hopper.log` -> `hopper.1.log` ... `hopper.4.log`; the 5th-oldest is deleted (5 runs kept).
- Cap: one run stops writing at 10 MB, with one last line "[log full at 10 MB...]". stderr still gets everything.
- Helper runs (`--fetch`, `--video`, `--crash-explain`, a forwarded link, `--uninstall`) never rotate or write the file. Lines logged before the file is chosen are held (64 KB) and written after the opening line.
- Level: info for `hopper` / `hopper_core`, warn for everything else; `RUST_LOG` overrides.
- Line: `2026-11-14 02:15:27.123 INFO  hopper::discord: discord: connected` (local time, ms).
- First line: `Hopper 0.71.0 started on Windows 10.0.26300 (26H2) (x86_64), data folder C:\Users\<user>\...`.
- Panics: a hook logs `panic at file:line: message` and then calls the old hook, so `crash.log` and stderr work as before.
- Copy log: whole file when <= 512 KB, else the last 2,000 lines (first line says so). Toast "Log copied".

## Secrets
- Audited every `log::` call (467, desktop + core + hopperd; single- and multi-line). None prints a CurseForge key (header only, never in a URL), a GitHub/panel/relay/mailbox token (headers only), a header, a settings dump, launch args or a share/invite code. So no call site needed changing.
- Safety net anyway: `applog::redact` runs on every line. Hides `key=` / `code=` / `sig=` values, `*token*` / `*secret*` / `*password*` / `*api_key*` values, `Authorization` / `x-api-key` / cookie headers, `Bearer ...`, JWTs, CurseForge's `$2a$10$...` key, `ghp_` / `github_pat_` tokens, Discord webhooks, `HOP-...` share codes, "invite/setup/join code: ..." and the Windows user name in `C:\Users\<name>`. Unit-tested.
- Not hidden: other paths (instance names/folders), mod names, panel URLs / IPs. Those are the useful part of a bug report.
- Seen, left alone: Mojang error bodies (first 500 chars) are logged at warn in `mcprofile.rs:320`; they have no token, but may name the account's profile.

- Tests (`cargo-test-changed.ps1 applog`, `... log_stamp`): 9 applog tests (5 runs kept and oldest dropped, smaller keep trims, size cap stops growth, redaction of 13 kinds of secret, plain lines untouched, line format, no-target line, start line, tail of a big file) + time stamp test: all pass.
- On screen (test exe, `HOPPER_DATA_DIR` scratch, `HOPPER_LOOPBACK=1`, port 47871; `state` showed 0 instances): log file exists with the start line (user name hidden). - NOT checked on screen: the panic hook (needs a panic; the hook only adds a `log::error!` before the existing hook), the 10 MB cap in the real app (unit-tested), "Copy log" on a >512 KB log (unit-tested), release exe with no console, a failing disk / read-only data folder.
- Test data: scratch root only, deleted afterwards. No real instances. Forward-focus check: the foreground window changed between before/after launch once; could not tell if that was me or the user, nothing else was clicked on the desktop.

## Notes for the maintainer
- Seen in the log of a test run: `ERROR : No localised string for en-US` (6x at start, from a UI library, no target) and `ERROR : RefCell already borrowed` (twice per MCP call; MCP-driven runs only, source not looked into). Both come from dependencies at error level.
- Hopper Server (`crates/hopperd`): when run as a service or the Windows launcher, it logs to `hopperd.log` in the start-up data folder (append only; the launcher renames it to `hopperd.log.old` once it's over 20 MB; env_logger's default line has a UTC time and level). The tray menu has "Open log" (launcher.rs). The web UI doesn't show the panel's own log (the Console view is the game server's), and there is no "copy log" or redaction. Changed nothing there; reusing `applog` for hopperd (rotation, redaction, a "Panel log" view) is a follow-up.
- `RUST_LOG=debug` still works but debug lines are redacted the same way.
- A dev run's stderr is no longer coloured (env_logger writes through our pipe).
- The log is cut at 10 MB by stopping, not rolling: a log loop keeps the start of the run, not the end.
