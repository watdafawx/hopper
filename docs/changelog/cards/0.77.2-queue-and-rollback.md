# Tasks wait their turn; "Roll back" in the load-problem notice

**Branch:** t3/fde6ff76 (t3/queue-instance-tasks-and-rollback)   **Commits:** 237835fd (queue), 88e9879d (Roll back)   **Size:** M + M
**Apps:** desktop only. Hopper Server has no "another task" refusal on mod actions and no load-problem notice in its web UI, so nothing to port.

## From -> to
- Before: starting an Undo, install, update etc. while another task changed the same instance was refused ("Another task is changing this instance").
- After: it queues per instance. The task list shows it with an hourglass and "Waiting for '<task>' to finish", it can be cancelled while it waits, and it re-reads the instance when its turn comes. "Close the game first" and Delete instance still refuse.
- Before: a jar that an update broke only offered "Turn off" (and Revert when a version need was known).
- After: an outlined "Roll back" next to "Turn off" when History has the update that brought the current file. Tooltip "Back to 15.10.4, from before the update on 16 Nov". Runs History's Undo, then the notice checks again.
