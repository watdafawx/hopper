# Mod peek: read a CurseForge mod's comments in a Comments tab

**Branch:** t3/peek-curseforge-comments   **Commit:** a05688b   **Size:** L
**Apps:** both (desktop mod peek; Hopper Server mod peek + Browse project page)

Mock: https://claude.ai/artifact/GBXVhz5BrnDGRdezmCXbBU (picked A, a Comments tab: same place players already look for Files and Dependencies, and a long thread doesn't push the description away).

## From -> to
- Before: the peek showed Description / Files / Dependencies only; reading comments meant opening curseforge.com.
- After: CurseForge mods get a Comments tab: pinned first, replies under their comment (one level), 20 at a time with "Show more", "Open comments on CurseForge" link. Modrinth / GitHub / link mods show no tab.

## Notes for the maintainer
- The endpoint is the website's own, undocumented. Any change there degrades to "Comments couldn't be loaded" + link; the peek keeps working. The CurseForge key is never sent to it.
- Replies to replies are flattened to one level under the top comment, in order (the site nests them; we don't indent forever).
- gpui-kit 0.8 `Avatar` with `Size::Size(px)` sets the text box to size*0.5, so initials drop and wrap. Used `.small()` instead; worth a kit fix.
- Risk: serde_json rejects a lone UTF-16 surrogate in comment text; that page would show the error state.
- `HOPPER_TEST_COMMENTS` stays in release builds (reads a local file only when set), like the other test env vars.
- During testing another session's test build was holding MCP port 47833; my first hover/clicks landed on its empty Overview area (no change seen). Moved to 47867.
