# Idle Hopper stops ticking: the store poll waits for work

**Branch:** t3/store-poll-wait-for-work   **Commit:** d51a5be8   **Size:** S
**Apps:** desktop only (this is the desktop store loop; Hopper Server has no such timer)

## From -> to
- Before: the store's worker-message poll loop ran on a 50 ms timer for the whole session, waking ~20 times a second even with nothing to do.
- After: it blocks on an async channel that a message, a full-redraw flag or a job-progress tick signals, so an idle Hopper wakes ~never, while a burst of ticks still collapses into one redraw.

## Screenshots
No visual change (no mock, no UI change). Not applicable. One rig screenshot (shot1.png, during a Fabric API install) confirmed the progress bar was mid-download, but it is evidence, not a before/after.
