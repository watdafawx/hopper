# History: one row per pack update

**Branch:** t3/history-scroll-perf   **Commit:** 3f789e2   **Size:** M
**Apps:** desktop (instance + server History, one shared view) and Hopper Server web UI. Mock: https://claude.ai/artifact/LDwBAx4eVa4i6KMw3oX6Gc (option B).

## From -> to
- Before: a pack update filled History with one row per changed file (500+ rows after ATM10 1.79 -> 1.80).
- After: one group row, "Updated pack All the Mods 10 to 1.80.0", with a chip per kind ("50 updated", "50 rolled back", "50 removed", "34 added", "16 turned off", "450 configs") and Undo all. Open it: mods first (by kind, then name), then a closed "Changed 450 configs" fold with its own Undo all. Every row inside keeps its own Undo.
- Only updates made after this change are grouped (the update now writes a `.pack-update.json` mark in its History stamp). Older History stays as single rows.

## Files
- `crates/hopper-core/src/backups.rs`: pack mark, merge a pack's sets into one, mods-first order, per-kind counts, "N configs" label, JSON `pack` / `parts` / `counts`; test.
- `crates/hopper-core/src/server_pack_update.rs`, `src/gpui/store.rs`: write the mark after a pack update.
- `src/gpui/history_view.rs`: group row, configs fold row, Undo all.
- `crates/hopperd/src/mods_more.rs`: undo by a list of names; put-back looks across merged sets.
- `crates/hopperd/ui/src/ModBackups.svelte`: same group view, chips wrap, readable chip text.

## How tested
- `cargo test -p hopper-core --lib` 1428 pass; `cargo test -p hopperd` 368 pass; `cargo test --bin hopper` 89 pass, 1 fail (known `anim` overflow, not touched).
- Desktop on rig (slot 3, MCP, scratch HOPPER_DATA_DIR, seeded throwaway "Hist Pack" + "Tiny Pack"): collapsed, expanded, configs fold, single Undo, Undo all; dark, light, 960 pt.
- Web: scratch hopperd on FOX (`--portable --home --data`, loopback, port 8851), headless Chrome 1536x960 and 700x900, dark + light.
- Scratch data deleted on rig; scratch hopperd stopped.
- NOT tested: a real pack update end to end (the groups were seeded with the mark), remote Hopper Server History opened from desktop, undoing a downloaded mod inside a group.

## Notes for the maintainer
- Dark "removed" chip on desktop is 3.64:1: it's the theme's danger red, same as every dark "Removed" label in History (desktop `ink()` only darkens on light pages). Pre-existing; not changed here.
- Web chips now mix the kind colour with the text colour; other web chips (`.chip.warn` etc. in app.css) still use the raw colour on light themes and have the same low contrast.
- Rig slot 3 was taken over once by another session's push mid-test (app killed, relaunched).
