# Keep everyone in step: no extra copies of a group pack

**Branch:** t3/c0d54d9b   **Commit:** d9716a0   **Size:** M
**Apps:** desktop only (Hopper Server has no friends sync)

## From -> to
- Before: a group pack followed by "Keep everyone in step" was recorded as followed only after its install finished; a failed, cancelled or interrupted install left an instance with no follow, and the next start made another copy (players saw 3 ATM10s, one synced).
- After: the follow is recorded as soon as the instance exists; an unfinished install shows the update waiting on that instance and finishes into it (retry, Try again, next start). No new copy.

## Notes for the maintainer
- Cancel decision: the instance and follow stay; it shows as a failed update ("Cancelled") and Hopper tries again later, same as cancelling any follow update. Never deletes the instance.
- Old duplicates on players' PCs are NOT adopted: install_share writes nothing that marks an instance as an unfinished auto-follow (same name/pack as a manual install). Players delete extras by hand.
- Small gap left: Hopper killed inside the CurseForge/Modrinth pack install after the pack's hopper.json is written but before the follow is recorded (copying overrides, seconds) can still leave one unfollowed copy. Closing it needs the id passed into modpack::install.
- `redeem` (share code with an invite) records its follow after install + join too; manual, never re-runs by itself, so no duplicate loop. Left as is.
