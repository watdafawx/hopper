# Updates and syncs replace old jars, turned-off ones too

**Branch:** claude/old-copy   **Commit:** see `git log claude/old-copy`   **Size:** M
**Apps:** both (shared rule in hopper-core; desktop and Hopper Server use the same code; remote servers get the same Copy/Disable/Delete ops over the API)

## From -> to
- Before: a sync that found the mod turned off on the server skipped it (guard from 0.56.0), so the server never got the new version; earlier builds added the new jar on beside the old off one ("Old copy" chip). Pack/mod updates replaced only the first tracked copy of a project, so an existing double kept its other copy.
- After: sync puts the pack's newer file on the server in the same on/off state as the copy it replaces (off stays off) and deletes the old file. Pack updates and single-mod updates replace every tracked copy of the project, on or off; the new file takes the state of the copy that was on.

## Cases (hopper-core tests, throwaway folders)
| Case | Result |
|---|---|
| Pack update: mod on | new on, old gone (backups/History) |
| Pack update: mod off | new `.jar.disabled`, old gone |
| Existing double, one on one off | one new file, on; both olds in backups |
| Existing double, both off | one new file, off |
| Pack drops a mod (on + off copy) | both copies go |
| Your own mod | untouched |
| Sync: off on server, pack newer on | server ends `armor-2.0.jar.disabled` only |
| Sync: off on server, pack newer off | server ends `frames-2.0.jar.disabled` only |
| Sync: on on server | `lib-2.0.jar`, old gone |
| Sync: new mod / server-only mod | added / left alone |
| Sync: same file already off there | nothing |
Server folder after sync (test): armor-2.0.jar.disabled, frames-2.0.jar.disabled, fresh-1.0.jar, lib-2.0.jar, yours-1.0.jar.

## Notes for the maintainer
- Existing old copies: the Old copy chip stays; nothing is deleted on startup. User removes them via the chip.
- Recommend a one-click "Remove all old copies" (a mod list has dozens on TNP-LL8-sized packs); not built.
- If a server has several off copies of one mod, the sync replaces one; the rest show the chip.
- Disable is a separate op after the copy: if it fails the new jar is left on.
