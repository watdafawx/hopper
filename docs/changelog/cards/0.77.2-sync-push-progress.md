# Sync: pushing a big pack no longer floods Hopper Server, and each mod shows how its push goes

**Branch:** t3/sync-push-progress-batching   **Commits:** cd352176 (part 1), fcab7f18 (part 2), fe2ea283 (fixes found by the rig proof)   **Size:** M
**Apps:** desktop + Hopper Server backend. The web UI has no paired-instance Sync page or push, so it has nothing to change.

## From -> to
- Before: pushing a pack to a remote server made about 1,000 panel requests in the first minute. `/fs/<id>/text` alone was 488 of them. The panel could answer 429, which blanked the server list and the Sync tab ("Can't reach …"). The whole push showed one spinner.
- After:
  - Config texts are read in one batched request (`POST /api/v1/fs/{id}/texts`). This covers the crash check, the classify step and the config drift check.
  - No compares run during a sync, and the sync's own echo afterwards starts none either. There is one compare at the end.
  - On a 429, both the server list and the Sync tab keep what they show. They say "Hopper Server asked to slow down. Trying again in N s." and ask again by themselves.
  - Each ticked row shows its state: Waiting, Uploading N%, Added/Updated, or Failed with the reason in a tooltip and a Try again button. The footer says "Pushing 3 of 7…" with a small bar. At narrow widths the row shows only the % or an icon.

## Found, not fixed (not from this branch; checked on main)
- **Instance → Server tab at 960 pt with its side panel:** the Sync list is wider than the room left, so the right column (Server → Pack and the row buttons) is cut off. main does the same (`narrow-side-panel-clipped-on-main.png`). This breaks the "no wrap/clip with side panels" rule. It needs its own fix.
- **`widgets::done_mark` in the light theme:** the green text on its tint is 3.89:1, under 4.5. The widget is used across the app, so the fix belongs in the shared widget.
- During a push, `/servers/<id>/mods` and `/neoforge` are each read about 9 times a minute, about the same as on main. Likely source: the Mods tab's server column compare and `server_mods::detect`.
