# Nodes in Hopper desktop: each node's own light and line, new servers on a node, Update from the main

**Branch:** t3/finish-a3-node-streaming-desktop   **Commit:** 4bcf281 (on top of 88ade11, the A3 web work)   **Size:** L (A3 Part 4 + live checks)
**Apps:** both. Desktop is new here; Hopper Server gets one read route (`GET /api/v1/nodes/live`) and "list" changes when a node connects, drops or changes state. The web UI was already done in 88ade11 and is unchanged; checked in a real browser.

Mock: https://claude.ai/artifact/UFmLe1kq9KCwewfw4oa5aH

## From -> to
- Before: a node group in desktop's Servers list used the panel's light, said nothing about the node, had no +, and nodes could only be updated from the web UI.
- After: the node group's light and line come from the node itself (Update available, Updating, Update failed, Update needed, Newer than this panel, Reconnecting, Offline · last seen), + opens New server on that node, and the group menu has "Update to hopperd 0.63.0" with a confirm.

## Notes for the maintainer
- Red line contrast (3.99 / 4.28:1) is the theme's danger colour; the web list uses grey for the same lines. Pick one for both apps (a darker danger for text, or grey like the web).
- A failed update is forgotten when the main restarts (kept in memory).
- `--home` on a node leaves `node.json` in `--data`: the node never connects until it's copied back (scratch only so far).
- Shared files with the parallel switch/refresh agent: `src/gpui/servers.rs` (groups, group_head, two new fns after it, and the Making filter in server_list), `src/gpui/store.rs` (Msg variants, a field, discover_servers, Making.node). Their hopper-core `off` field wasn't in this branch.
- Shared perf slots built a stale hopper-core from another worktree once (`off` field): touch the changed files before testing.
