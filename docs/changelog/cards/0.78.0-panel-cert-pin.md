# Server panels: trust a self-made certificate once, then only that one

**Branch:** t3/panel-cert-trust-on-first-use   **Commit:** 26502988 + 6941b947 (merged with main at bd9ffa3e)   **Size:** M
**Apps:** desktop only. Hopper Server's web UI has no Crafty / MCSS / Pterodactyl screen, and its pairing with the desktop already pins its certificate (pair code over the CA fingerprint), so nothing to change there.

## From -> to
- Before: a Crafty, MCSS or Pterodactyl panel with "Self-signed certificate" on accepted any certificate at all, and Hopper sent the panel's API key to whoever answered.
- After: the first Save and test shows the certificate's SHA-256 and asks "Trust this panel's certificate?" (nothing is sent before that). After that Hopper connects only while the panel has that certificate. If it changes, Hopper stops before sending the key, shows the old and new fingerprint, and "Trust the new certificate" works only after ticking "I changed the panel's certificate myself". Panels saved before this pin the certificate they have on the next connect and say so once. Panels with a real (CA-signed) certificate keep the normal check.

## Notes for the maintainer
- Side finding, not fixed: FTPS server files (`remotefs/ftp.rs`) with "Self-signed certificate" still accept any certificate via `tls::client_config(true)`. Same fix would fit (the pinned config is reusable).
- Also fixed on the way: the panel form's address blanked whenever settings changed while the form was open (store observer reset it to ""). Only visible now because the form stays open for the trust prompt.
- The migration notice is a normal info toast (auto-hides after ~5 s); the pin shows under the address in Settings afterwards.
- "Connected: 0 servers ()" shows empty brackets when a panel has no servers (old wording, left alone).
