# Sync: a timing line for every comparison (to find the slow step)

**Branch:** claude/sync-timing-log-9eb5c4   **Commit:** c1fe372   **Size:** S
**Apps:** desktop (writes the file) + Hopper Server (one line in its own log for the remote read). No UI change.

## From -> to
- Before: no way to see where Sync's comparison spends its time.
- After: each time the Sync tab compares (open, refresh, rescan) it appends one line to `sync-timing.log` in Hopper's data folder.

## Where to read it
`%APPDATA%\Hopper\data\sync-timing.log` (or `<data folder>\sync-timing.log` if Hopper's folder was moved; Settings shows it). Newest line last; starts with `[unix seconds]`. The app has no Logs page for Hopper itself (the Logs page is the game's), so no UI was added. Hopper Server writes a `sync mods read: ...` line (server-side time only) into hopperd's own log (`hopperd.log` in its data folder when run as a service) for each Sync request.

## Example line (throwaway Bench pack, 1,160 jars each side, cold caches)
`[1794026349] sync compare: total 1507 ms (crash and config reads 0 ms, NeoForge read 0 ms, pack marker read 0 ms, turned-off jar scan 0 ms in 2 calls, server scan 2 ms, jar reads (not in cache) 92 ms for 1,160 jars, sha1 of unknown jars 186 ms for 1,160 jars, Modrinth side lookups 1138 ms for 1,160 jars, Modrinth project lookups 0 ms, side tagging (all lookups below) 1403 ms for 1,160 mods, pack scan 1497 ms, diff 6 ms; stages overlap)`
(That label now reads "side tagging (includes the sha1 and Modrinth stages)".) Stages overlap (pack and server read side by side), so they can add up to more than the total. A remote server shows `server fetch (1 request to Hopper Server) N ms for M entries` instead of `server scan`; a failed Modrinth call shows `, N failed`. Only counts and times: no file or mod names. Bytes of the remote reply are not logged.
Even on this fixture, the cold run shows what the previous session could not: Modrinth lookups were ~75% of the time (needs network; each new jar costs once, then it is cached).

## Files
- `crates/hopper-core/src/synctiming.rs`: new stage timer, line format, file write, 4 tests
- `crates/hopper-core/src/rigsync.rs`: times pack scan, server scan/fetch, off-jars, diff
- `crates/hopper-core/src/scan.rs`, `modrinth.rs`, `serverpack.rs`: jar reads, sha1, Modrinth, server pack list
- `src/gpui/rigsync.rs`: begins the run, times crash/config/NeoForge/marker, writes the line
- `crates/hopperd/src/api.rs`: logs a line for each Sync mods request

## How tested
- Tests: `synctiming::` 4 pass (format, no stages, run/no-run, thousands); `cargo-test-changed` 106 pass (hopper-core + hopperd).
- On screen: scratch `HOPPER_DATA_DIR`, Bench Pack instance + server (generated 1,200 jars), MCP 47839; opened Sync, line appeared in the scratch `data\sync-timing.log` (warm and cold-cache runs).
- NOT checked: a remote Hopper Server pair (no scratch panel run; remote branch compiles and is covered only by the unit test of the format); hopperd's log line at runtime; the final label rename was built after the run (string only); `sync_bench` unaffected.
