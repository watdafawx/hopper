# Resizing: header, tabs and toolbars keep up with a dragged edge

**Branch:** t3/fix-resize-lag-fit-side-panel   **Commit:** ab7ae9e   **Size:** M
**Apps:** desktop only (Fit is desktop; Hopper Server's web UI lays out in the browser, no lag there)

## From -> to
- Before (0.73.0): while dragging the mod peek dock's edge or resizing the window, the page header, instance tabs and Mods toolbar were drawn at the layout the *previous* frame needed (clipped, or with room left over), one level step per frame. It looked like the layout trailed the pointer.
- After: each frame is drawn at the right level for that frame's width once the row has been seen at that level. Steady layouts are pixel-identical to before.

## Root cause
`widgets::Fit` measured each row after layout (prepaint), changed level and notified, so the right level only showed on the next frame (one wrong frame per level step, one step per frame). Frame cost was not the problem: 0.72.8 vs 0.73.0 release builds 11.0 vs 10.2 ms mean frame. Panel width is saved only at drag end (no per-move disk writes).

Fix (all in `widgets.rs` Fit internals, plus one line per page):
1. Pages publish their room while they render (`set_page_room`). Each Fit learns its offset to it when measured and, from widths it has seen overflow, picks the level before layout.
2. Widths are kept per row key (last 4), so the Mods bar's `hint` flipping at 1100 px no longer wipes them.
3. A level change found in prepaint notifies after the frame (`cx.defer`). A notify inside the draw only dirties the view and ancestors and is cleared at frame end, so the cached page Part was reused, leaving the instance tab bar stuck clipped (seen at 1100 px before this fix).

# Combined with "Fit pages beside side panels" parts 2/3 (merge on t3/71a7aff0)

**Base:** main 8dc78a0 (parts 2/3 already in) + ab7ae9e merged. Debug profile on rig (slot 2), same 300-mod scratch instance, dock 30 rem, 1455x907 @1.75.

## How the two were combined
- Kept from the resize fix: `set_page_room`, per-key widths (`others`), `decide()` prediction, `notify_after_frame`.
- Kept from parts 2/3: `measured()`, `fit_seen`, `short_by` (rem), `room_probe` / `probe_raw`, the probe re-measure, library.rs `PAGE_MIN`, `cap_dock`, `squeezed` list fold.
- Library publishes the page room **after** the dock cap and the list fold (`detail_w = win - side - peek_w - friends_w`), so prediction uses the width the page really gets. Servers publishes after `detail_w = room`. No other page uses Fit (rigsync's `Fit` is a separate struct).

## Four extra fixes the merge needed
1. **Probe rows learn the offset from the raw room** (before flooring at 0). The hero actions' floored room left a stale offset and repeated 7->8 steps. `probe_offset` folded into `offset`.
2. **Fit context** (`Fit::context(key)`, up to 16 offsets): the hero pills' room depends on the actions' level and whether the art is dropped. One offset per (actions level, art) pair. Without it: 1 wrong frame per drag. Test `a_row_beside_another_keeps_up_with_its_level` fails without it.
3. **`short_by` keeps up with the page**: computed from page room - offset in the same frame; a stale value notifies after the frame once (then resets, which stops a ~110-notify/1.5 s loop seen in testing). Test `short_by_keeps_up_with_the_page`.
4. **Automatic list fold snaps** (`fold_snap`): part 3's 220 ms slide meant `detail_w` didn't match the laid-out page during a window resize (many wrong steps). Player folds / drag ends still slide.
