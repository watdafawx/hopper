# Group packs: Undo in History reaches the group and stays undone

**Branch:** t3/c6084418   **Commit:** 2c65d92 (fix 10243ab)   **Size:** M
**Apps:** desktop only (group sync is desktop-only; Hopper Server has no group copies)

## Cause (two bugs, both in two-way group sync)
1. **A quick Undo was invisible to the others.** A member compares a code only with the last code it took from that sender, and the relay keeps only the newest code per sender. Undo a mod someone else updated before they've read your echo of it, and your new code is exactly what they last got from you: no difference, so they keep the update. Your PC is undone, theirs isn't. (Repro: unit test `an_undone_update_stays_undone_everywhere`, red before the fix for "A undid, quick".)
2. **Undoing an update or removal of a pack mod never synced.** Undo puts the pack's own file back, so the share code stops listing the mod ("as the pack has it"). Other members only noted "putting back the modpack's own file isn't done by sync" and kept the update. Most mods in a CurseForge-pack group are pack mods, so this was the common case.

Not the cause (checked): Undo isn't blocked for group mods; follows keep a History entry Undo can use (it downloads the old file); the plain follow path skips group copies; mod identity matches; the `~pack` guard only acts between pack versions; config sync carries its full stamped state, so it doesn't have bug 1.

## From -> to
- Before: Undo of an update in a group pack put the old file back on this PC only. The group kept the update, and the mod row could read "Removed by Mia" while the mod was there.
- After: Undo is sent like any other change. Each code now stamps the mods it changes itself ("made in this code"), and members take those even when the code matches their last one from that sender. A member who gets "as the pack has it" for a pack mod puts the pack version's own file back (CurseForge packs, from the manifest). The row says "Updated by Mia".

## Notes for the maintainer
- Modrinth packs: putting a pack mod back to the pack's file still only notes "isn't done by sync" (the mrpack index has no project ids). Same bug 2 there.
- History wording: an Undo (and a member's undo put back here) reads "You switched Polytone 26.2-6.10.1", not "put back 6.8.6". history_view.rs is another agent's; left alone.
- Wire: the new stamp is `{seq: 0, by: <sender>}`. Older Hopper ignores it (it filters seq > 0); the relay passes marks as they are.
