# Description tables: linked banner grids show full size (no tiny images, no extra column)

**Branch:** t3/fix-peek-description-image-table   **Commit:** 9773de3   **Size:** S-M
**Apps:** desktop + Hopper Server (same parser; web UI checked by test only, see below)

## From -> to
- Before: Enchantment Switch's Description tab showed its banner table as a 3-column grid of empty dark cells with ~25x7 px images in the corners; the Discord/Twitter/... badges stacked one per line.
- After: a 2-column grid of banners that fill their cell at their own shape (up to the page's 410 px); the badges sit in one row at their page sizes. Links still open (tile click handlers unchanged).

## Root cause
1. `&emsp;` was not a known entity, so the spacer cell `<td>&emsp;&emsp;</td>` held the text "&emsp;&emsp;". A row with text is not an "image row", so the whole table fell to the Markdown table view, which draws images at text size (tiny) and keeps the spacer column (3 columns). The same entity between the badges did the same to them.
2. (Found on screen, my own regression otherwise) Badge/grid tiles decode with the `image` crate, which can't read SVG, so shields.io badges drew blank once they became a badge row. The old Markdown path drew them through GPUI.

## Fix
- `richtext.rs`: decode `ensp emsp thinsp hairsp numsp puncsp emsp13 emsp14` as blanks; `image_row` drops empty cells (spacer columns). Blank rows were already dropped by the parser.
- `imgcache::is_svg` + `thumbs::source_in` hand SVG files straight to GPUI; `widgets.rs` badge height falls back to the page's height when the size is unreadable (SVG).

## Notes for the maintainer
- Tables that mix text and images in a cell still go to the Markdown table view (gpui-kit TextView), where images stay text-sized. Not changed here (needs a new view); say if you want it.
- Wide panel: the banners cap at 410 px and sit left in their cells, so the gap between columns grows (54 px). Matches "up to natural size".
