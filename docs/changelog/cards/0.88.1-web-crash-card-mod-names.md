# Server crash card: a mod's name and icon, not its id

**Branch:** t3/web-crash-card-mod-names   **Commit:** f9638dd6   **Size:** M
**Apps:** Hopper Server (web UI). Desktop already does this (`peek_mod_id`, `lacks_line`); the shared lookup is new in hopper-core so desktop can adopt it later.

## From -> to
- Before: the crash card printed raw mod ids ("Needs arcane_framework 1.0.0 or above", the same id in the sentences, in "What to do", and as a fallback in switch rows), with no icon and no link.
- After: each id shows the installed mod's icon and name, or the mod site's project icon and name (subtitle left off: "Arcane Framework"). Clicking a project opens its page beside the card; clicking an installed mod opens its peek. An id nothing resolves stays as the id, in a quieter mono style.

## Files
- `crates/hopper-core/src/modref.rs` (new): one lookup: id -> installed jar / loader / site project (icon, name, page); 3 tests.
- `crates/hopper-core/src/install.rs`: `name_head` made `pub` (subtitle trim, same as desktop).
- `crates/hopper-core/src/lib.rs`: `pub mod modref;`.
- `crates/hopperd/src/mods_api.rs`: `GET /api/v1/servers/{id}/mods/for-ids?ids=a,b` (read access via `entry`/`require`, ids validated, max 12, cached 1 h / 2 min for misses).
- `crates/hopperd/ui/src/lib/modids.js` (new, pure) + `tests/modids.test.mjs` (4 tests): replace ids in sentences by names.
- `crates/hopperd/ui/src/lib/modids.svelte.js` (new): asks the route, keeps the answers.
- `crates/hopperd/ui/src/lib/ProjectPeek.svelte` (new): side panel with the project's page (reuses `BrowsePack`, same panel as ModPeek/AuthorPeek).
- `crates/hopperd/ui/src/ServerCrash.svelte`: Needs row, switch fallbacks, sentences, install button/toast use names; icon + name snippet; quiet raw id.
- `crates/hopperd/ui/src/ServerLogs.svelte`: hosts the project peek next to the mod peek.

## Notes for the maintainer
- The web UI has no separate "missing dependencies" banner; the only places that printed ids were: Needs row, switch-row fallbacks (2), the sentences/steps (`named`), the Install button text and toast. All now use one `idMod` snippet / `readIds`.
- Case left as it was: an id whose jar is present but disabled can still show "Install" (existing behaviour).
- Desktop could call `hopper_core::modref::resolve` too instead of its own copy; not done here (out of scope, `src/gpui` untouched).
