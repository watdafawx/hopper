# Hopper Server Mods tab: Remove and Update fold into the row ⋯ menu when narrow

**Branch:** t3/hopperd-mods-row-fold-menu   **Commit:** see report   **Size:** M
**Apps:** Hopper Server web UI only (parity with desktop 0.76.0; desktop untouched)

## From -> to
- Before: web Mods rows kept the Remove button and the Update / Changelog column at every width, so the name shrank to a few letters when the page was narrow.
- After: same order as desktop. Remove moves into the ⋯ menu first (it was already there), the name keeps about 12 characters, then the Update column goes into the menu as "Update to <version>". When folded, the ⋯ button is always shown (it is the only way to reach them), as a real `<button>` with a focus ring.

## How tested
- Tests: `cargo test -p hopperd` 369 passed / 3 ignored. `pnpm build` ok. hopperd built through `cargo-ccd1.ps1`.
- On screen: scratch hopperd (`--portable --port 8812 --home/--data/--servers-root` in scratchpad, `HOPPERD_SERVICE=hopperd-test`, `HOPPER_LOOPBACK=1`, 127.0.0.1 only), one scratch server with 12 hand-made fake jars, headless Chromium via Playwright. Real `%APPDATA%\hopperd` not touched (folder date unchanged, Oct 28).
- Update data is **mocked in the browser**: the scratch box has no CurseForge/Modrinth link, so Playwright adds `source` + `update` to 5 mods in the `/mods/list` reply and answers `/mods/updates`; the update POST is caught and answered with an error (it never ran). So "Update to" is proven to fire the right request, not to install.
- NOT checked: a real update install; the real ⋯ "Update to" with a locked version (Shift rule is the same function as the row button); peek panel contents (the mocked source makes the panel show an error); touch/hover-only ⋯ on wide rows (unchanged, still hover-only there); contrast (no colour changes); other themes than Hopper Dark / Light.
- Not changed: resource packs, shaders and data packs. The web UI has no resource-pack or shader tab, and the Data packs tab is a different list with no Update/Remove columns. Only the Mods table (which also lists data-pack jars) has these rows.

## Notes for the maintainer
- The web ⋯ hover-only visibility pre-exists: at wide widths a keyboard user cannot focus ⋯ (it is `visibility: hidden` until hover/select). Not touched here.
- Added a global `.ib:focus-visible` outline in `Mods.svelte` (scoped to that component), covering Columns / ⋯ / Remove icon buttons.
