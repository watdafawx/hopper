# Mod peek: search a mod's GitHub issues in an Issues tab ("is this a known bug?")

**Branch:** t3/mod-peek-github-issues-tab (worktree t3-94beb62c)   **Commit:** 35c9fd4   **Size:** L
**Apps:** both (desktop mod peek / Browse; Hopper Server mod peek + Browse project page)

Mock: https://claude.ai/artifact/MTz6yTWJ6o2vYmoEGYkmLV (picked A: GitHub-style rows where the title wraps and the labels sit under it. In a narrow peek the title is what a player scans for "my crash"; B cut titles to one line.)

## From -> to
- Before: the peek had an "Issues" link only; checking for a known bug meant opening GitHub.
- After: when a mod's issue tracker (CurseForge issues link, Modrinth issues_url, or a GitHub mod's own repo) is on github.com, the peek gets an Issues tab after Comments: search box (searches when typing pauses for 0.5 s, or on Enter), Open / Closed / All, 20 issues at a time with "Show more", each row with open/closed icon, title, label chips, number, who opened it and when (or when it closed), comment count; clicking opens it on GitHub. "Open issues on GitHub" opens the same filter/search on the site. Trackers elsewhere (Xaero's own site, Discord...) show no tab; the Issues link stays.

## Notes for the maintainer
- Search uses GitHub's search API: 10 a minute without a token (30 with). The tab searches only when typing pauses, caches every answer for the session, and a refusal shows "GitHub is busy, try again in a minute." with the link. The rate-limit check is separate from source updates' pause, so a busy search never pauses update checks.
- Hopper's GitHub token is sent when set (never logged); same token the GitHub-sourced mods use.
- Pull requests are dropped from the list; a page of only PRs looks further (up to 3 pages).
- Hopper Server: the browser sends only a project number; the server resolves the repo from that project's own links, validates owner/repo to `[A-Za-z0-9_.-]`, and only calls api.github.com.
- At the narrowest peek width the tab bar (gpui-kit TabBar) overflows: "Issues" is cut until the bar is wheel-scrolled. Pre-existing kit behaviour (the kit's `.menu(true)` would add an always-visible overflow button); not changed here.
- Web `.seg` styles are per component (Browse, BackupTargets, Issues each style their own); worth moving to app.css.
- `HOPPER_TEST_ISSUES=<dir>` test hook (list.json / search.json, marker files busy / fail / slow) stays in release builds, like the other test env vars.
