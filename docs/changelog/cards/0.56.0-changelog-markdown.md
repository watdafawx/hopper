# Changelogs show headings, bold, code and bullets instead of raw Markdown

**Branch:** claude/changelog-markdown   **Commits:** 034a701, 238263a   **Size:** S
**Apps:** both (one fix in hopper-core's changelog loader, used by the desktop and by Hopper Server's web UI)

## From -> to
- Before: a CurseForge changelog written in Markdown (Mystical Agriculture Plus) showed `# Changelog`, `**bold**`, backticks and `[x](url)` literally. Cause: CurseForge keeps the typed Markdown as text inside HTML paragraphs, and Hopper only read it as HTML.
- After: when the parsed HTML still holds Markdown (a `# Heading` line with no real headings, or `**bold**`/backticks in two or more blocks) it is parsed as Markdown. Real HTML and plain text are unchanged. Changelog headings are now body-sized (bold), so they no longer outgrow the dialog title.

## Notes for the maintainer
- Applied everywhere: every changelog in the desktop (Versions, file changelog, Hopper's own what's new) goes through widgets::changelog_text, so the heading size change covers all; every CurseForge changelog (desktop, update review, web UI) goes through source::changelog.
- Heuristic can misfire on a changelog that genuinely mentions two `code`/`**` spans in plain paragraphs; then it is read as Markdown, which is what the author most likely meant.

- `[text](url)` links CurseForge auto-linked (`<a>` inside the parentheses) in Markdown-typed changelogs are not specially handled.

## Second case: Lucky's Spelunker's Charm II 5.1.0 (monospace, one paragraph)
- Before: the whole Keep-a-Changelog text showed in monospace as one paragraph, `#`, `##`, `-`, `**` and `[#28](url)` literal (before2-dark-100.png, before2-light-125.png).
- Cause (not provable without the real data): the text is Markdown inside code (`<code>`/`<pre>`) with its line breaks lost (new lines became spaces, blank lines double spaces). The first fix did NOT cover it: it skipped anything with code in it and needed line breaks. Test shape: cl2-flat-in-code.html.
- Fix (richtext.rs): `parse_changelog` also reads a changelog that is only code as Markdown when it has a `# Heading` (or 2+ bold pairs), and `restore_breaks` puts breaks back, only when the text has no line break at all: before a ` ## ` mark, before `- ` + capital letter / `[` / backtick, and at runs of 2+ spaces. Modrinth and GitHub release notes go through the same restore (`parse_markdown_changelog`). Real code blocks, inline code in prose, "C#" and multi-line Markdown are untouched.
- Tests: changelog_with_lost_line_breaks_comes_back (in p, pre, code, Markdown), changelog_markdown_in_code_keeps_its_lines, real_code_blocks_stay_code; full hopper-core lib suite 1053 pass.
- After: after2-dark-100/125.png, after2-light-100/125.png: headings, paragraph, bullets, bold, `#28` as a link (orange, underlined); nothing monospace. Measured: heading line 14 px = title 14 px at 100, 18 = 18 at 125; text 16 px from the left padding; text widest line ends 440+ px inside the right edge (no overflow). Link click in the browser not clicked (uses the same link handler as before, with the dialog's open_link).
- Same renderer places: update-all review, mod peek, Hopper's own what's new all use changelog_text / source::changelog, so nothing else to change. NOT checked on screen: those dialogs.
- Open risk: a changelog whose real data does not look like this shape; the heuristic also needs a heading mark. Single-space headings ("# Changelog All notable") cannot be split from their paragraph.
