# Big mod lists use far less memory

**Apps:** desktop only (the web UI's images are the browser's own)

## From -> to
- Before: every picture Hopper showed (mod icons, banners, Browse cards, screenshots, server art) was decoded at full size and kept until Hopper closed. Scrolling a 1,188-mod list ended at about 646 MB working set / 749 MB private.
- After: pictures are decoded no wider than they are shown and kept to a 96 MB budget, dropping the least recently used. The image viewer frees its picture when it closes. The same scroll ends at about 454 MB / 548 MB. Jar scans at start-up use 3 threads instead of 8 and freed memory goes back to Windows; the start-up peak on a copy of a real pack fell from about 529 MB to 433 MB.

## How tested
- Memory numbers were measured on a fake 1,156-mod pack and on copies of the real instances (read-only), with the release-like local build; icons at 100/125/150 % look the same (mean pixel difference 0.21-0.36 of 255 in the crops).
- Start-up CPU fell from about 149 to 91 CPU-seconds in one measured run.
- NOT checked: dropping an icon and drawing it again on screen (unit-tested only); the image viewer window opened from a mod's gallery; some pictures (account heads, skins, world icons, pack-update card icons, the setup wizard) still use the old path; light theme and 200 % zoom.
