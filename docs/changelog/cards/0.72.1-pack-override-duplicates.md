# A mod the pack ships is the pack's; "in twice" only warns where the game refuses

**Branch:** t3/fix-pack-override-duplicates   **Commit:** bec2fae   **Size:** M
**Apps:** desktop (the fix is in hopper-core, so Hopper Server's mod checks get it too). The web UI's own "in twice ... Keep newest" line (`Mods.svelte`) is left alone: it means the same project listed twice, not a loader refusal.

## From -> to
- Before: a pack that ships a mod jar in its overrides had it recorded as "added by you", sometimes named after a stranger's CurseForge re-upload ("CC Tweaked Compat"), and the Mods tab said "1 mod is in twice: the game won't start with both" on NeoForge, where that is false.
- After: the jar is the pack's, named "CC: Tweaked", no warning. A copy the player added gets a quiet blue note: "CC: Tweaked is in twice. Only 1.120.2 loads; the other copy does nothing." Fabric / Quilt keep the warning.

## Notes for the maintainer
- NeoForge keeps the newest copy of a mod id (FancyModLoader `UniqueModListBuilder.selectNewestModInfo`: sorts by version, keeps the highest, logs "Found N mods for first modid X, selecting most recent"); ATM10's own `debug.log` shows it. A fatal "Found duplicate mods" only happens when a secondary mod id repeats across the chosen files, which still shows the warning.
- Existing installs (ATM10, TNP Limitless 8) are fixed without reinstall: both have the pack zip cached, so the override list is known on next load. Without a list nothing changes.
- A claimed override jar has project 0, so it counts under "Unknown" in the filter rail, like other pack-shipped jars with no project.
- "Remove other copy" in the note removes the lower version, as the warning's action did.
