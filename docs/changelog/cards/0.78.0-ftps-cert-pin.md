# FTPS server files: trust a self-signed certificate once, then pin it

**Branch:** t3/ftps-cert-pin   **Commit:** 0307e0b4 (+ merge of main f7ab7929)   **Size:** M
**Apps:** desktop only. Hopper Server (hopperd) has no FTPS (its offsite targets are folder / SFTP / S3 / Hopper), so nothing to port.

## From -> to
- Before: an FTPS site with "Self-signed certificate" ticked accepted any certificate, so someone on the network could sit in the middle and read the password.
- After: same rule as the Crafty / MCSS / Pterodactyl panels. First connect shows the SHA-256 and asks before any user name or password is sent. Later connects work only while the server has that certificate. A changed certificate stops before the password, shows old and new, and "Trust the new certificate" works only after ticking "I changed the server's certificate myself". Sites saved before this pin their current certificate on the next connect and say so once. Normal CA certificates are checked as before.

## Notes for the maintainer
- A refused certificate stops inside the TLS setup, before USER, so the password is never sent.
- The self-signed tick no longer means "accept anything" anywhere; the accept-all verifier is deleted.
- Editing host, port, protocol or the tick clears the pin and asks again.
- Pre-existing: `knock_on` dead-code warning in crashdetect.rs.
