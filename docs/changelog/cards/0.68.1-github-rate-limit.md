# Groups: GitHub's hourly limit shows once and waits for its reset

**Branch:** t3/github-rate-limit-dedup-backoff   **Commit:** 8287766   **Size:** M
**Apps:** desktop (+ hopper-core, which Hopper Server shares; see notes)

## Cause (why the friend got a flood of toasts)
- Group retries are keyed by the newest waiting relay event. Every new event from any member reset `failures` to 1, and the toast fired on `failures == 1`. So each event meant a new toast, plus an OS tray toast when the window wasn't focused.
- The retry delay was 2–15 s, forever (`failed_follows_wait_longer_each_time_up_to_15_seconds`): about 240 tries an hour, all against an exhausted limit.
- Receivers looked up every GitHub mod with `releases/tags/<tag>`, one API call per mod per pack version. A failed merge re-ran the lookups. The follow path noted the error once per mod.
- Update checks were already one call per repo (ETag, every 30 min, trusted sources only). That's 10 calls at start for 10 repos.

## Call counts (pack with 10 GitHub mods)
| Path | Before | After |
|---|---|---|
| Member installs / follows a group pack | 10 API calls per member per pack version | **0 API**, 10 website downloads (sha256 checked) |
| While limited | a call per mod per retry, every 2–15 s | **1** API call, then every call waits locally until reset |
| Group merges (4 toggles on A, live test) | up to 10 lookups per merge | **0 API**, 3 website downloads |
| Update check (A start) | 10 (one per repo) | 10, then reused 10 min (lists) / 1 day (tags); after that the ETag check gets a free 304 |
Live fake-GitHub log: `fake-github-hits.log` (B's follow: 9 web 200, juliet web 404 → 1 api 403, then nothing).

## From -> to
- Before: every retry raised a new error toast, and retries every 2–15 s kept burning the limit.
- After: one notice, "GitHub is limiting downloads for now. Hopper tries again at HH:MM.", with an "Add a GitHub token" button when no token is saved. Retries wait for GitHub's reset time. Installs say once "N mods from GitHub aren't in yet: GitHub is limiting downloads until HH:MM. Update again after that."

## Notes for the maintainer
- No relay change needed: pins already carry tag, file name and sha256 in the share code, so it works for older senders too.
- Hopper Server shares `http.rs`: its GitHub error text is now the player-facing limit message, and it gets the same pause and cache.
- The token row in Settings now shows even with "Allow mods from GitHub" off, since mod pages read GitHub too.
- `HOPPER_TEST_GITHUB` (127.0.0.1 only) points GitHub calls at a fake. Other GitHub calls (Hopper's own self-update) don't use it.
- Seen, not fixed: B's Friends panel says "up to date" while 1 mod is still missing (an existing label).
- Unrelated warning: `crashdetect.rs` `knock_on` is never used.
