# Friends groups: see if you're in step with the group, and Pull now

**Branch:** t3/friends-group-sync-status-and-pull   **Commit:** merge of main on top of 9cf9f7e5 / 8ff82ab7 (see git log)   **Size:** M
**Apps:** desktop only. Hopper Server has no friends groups (nothing in `crates/hopperd` touches groups or the mailbox).

## From -> to
- Before: a copy kept in step with a group gave no sign of whether it had what the group had. A mod from a GitHub link the player hadn't trusted was skipped silently, so a friend could miss a mod and nobody could tell. No way to ask "check now".
- After: every group copy says where it stands, in words (In step / Updating / Behind: close the game / Behind: needs you / Can't update / Offline / Sending your changes), on the instance page and in the Friends group. A **Pull now** button checks the group and takes everything in at once, and says what it did. The group's People list shows each person's chip (In step / Behind by N).

## Notes for the maintainer
- Found: a mod from an untrusted GitHub/link source was skipped silently and the member's code marked as taken in, so it was never retried. This is a likely cause of "my friend lacks a mod". Now listed, shown as Can't update, retried, and allowed with one button.
- Waiting for the game is shown only where it already waits (pack version, loader, jars the running game holds). Mods being added never wait; nothing about that changed.
- Phase 2 per member: In step / Behind by N is built from data we already have. "Why behind" (waiting for the game, can't apply) for other members **needs a relay change**: a new field on the recipe event (the relay validates `recipe_fields`). Not built.
- The strip's In step state can be dismissed (same as other notices).
- Merged with main; left-out mods now live in main's `PackCopy::owed`. The mod's name there is the repo's name ("ezactions") rather than the pack's display name.
