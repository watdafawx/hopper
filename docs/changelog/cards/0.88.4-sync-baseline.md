# A friend no longer ends up silently without a mod the group has

**Branch:** t3/prune-sync-baseline-unlanded-mods   **Commit:** see `git log` on the branch   **Size:** M
**Apps:** desktop only (group sync lives in hopper-core + desktop store; Hopper Server has no group copies)

## From -> to
- Before: if the CurseForge/Modrinth lookup failed while taking in a member's code, or a follow's first install missed a file, Hopper still saved that code as "already received". The mod never showed as a change again: permanently missing, no message.
- After: the saved "already received" code is cut back to what really landed. The failed/missing entries are retried the next time the member's code is read (their next publish, restart, Check now). The rest of the code applies at once. The task names what was left out.

## What was silent, what is named now
| Case | Before | Now |
|---|---|---|
| Lookup failed in a merge | skipped, code marked taken, never retried | entry cut from stored code, retried; task note "Couldn't look up X just now, so it wasn't added..."; `log::warn!` |
| Lookup never succeeds (file deleted on site) | n/a (lost) | applies the rest, no spin, later codes apply; one retry per read |
| Follow's first install missed a file | full code kept as follow's code; group copy seeded with it | only landed files kept; missing go to `left_out` + task note; `log::warn!` |
