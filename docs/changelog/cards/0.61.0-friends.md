# Friends: a panel to share and follow packs, groups, and follow codes

**Branch:** friends-panel   **Commits:** 72999b2 f07e6d4 5f8f609 b1c9cba fc70b9e 8258006 6155586 de63217 9ef588b e7e9932 (on top of the phase-1 store work)   **Size:** L
**Apps:** desktop only. Hopper Server has no friends or sharing screens yet, so there is nothing to keep in step there.

## From -> to
- Before: friends and sharing lived in the Peers dialog, with a "Paired" chip, an "From anywhere" option and its own invite countdown. A pack could only be shared with everyone. The side panel could draw only its top ~300 px after a popover opened ("panel breaks in half").
- After: a Friends button in the title bar (with a dot for news) opens a full-height dock beside the page, with **Friends** and **Your packs** tabs. Each pack is shared per friend or per group from a popover under its Share button. Friends' packs can be followed into an instance you choose. Groups: create, invite, join, keep in step, rename, add, take out, leave, delete. Share codes can carry a one-time "follow" part, and installing from one can follow the sender. The dock is the same one the mod peek uses, so it is one shared panel with one saved width.

## Notes for the maintainer
- The mock assumed a group lives on this PC; groups live on the relay and members see them, so the dialog says "Each friend gets an invitation and is in the group once they say yes." instead.
- The relay can't check a follow part without using it, and the code doesn't carry the sender's name, so Install says "whoever sent the code" and an expired follow part is reported after the install, as a task note.
- The mock's per-member "Following" status in a group isn't shown: the relay only knows each PC's "keep in step" switch.
- The relay won't let the owner leave, so the owner's menu has Delete instead of Leave.
- Installing a followed pack as a new instance can give two instances the same name.
- "for 1 minutes" fixed: code lifetimes read "1 minute" / "N minutes".
- Invite reuse edge: if a follow code is used while a plain invite is open, the new friend can look like the plain invite's, so the plain one is dropped early (the next click makes a new one). Two fast clicks before the relay answers can still make two invites.
- `cargo test --bin hopper` in a plain debug build fails `anim::tests::packed_frames_unpack_to_the_same_pixels` (`x as u8 * seed` overflows at seed 200). Not from this branch (`anim.rs` unchanged); the test wrapper's build passes it.
- Leftovers seen: title bar close button cut off at 960 px wide; the Browse project panel doesn't close on a click outside; the share and install dialogs don't use `DIALOG_TOP`; 7 other `cx.active_window()` uses that fail from a background window.

## Plain language pass (maintainer requirement: a 12-year-old or a parent must get it)
Every word on every Friends screen was rewritten for players: panel, tabs, empty states, buttons, tooltips, popovers, the follow chooser, share code dialogs, groups, errors and notices, and the same-network "Friends nearby" tab.

- **Gone:** relay, mailbox, sync server/service, recipe, publish, revoke, pair/paired, push/pull, token, "in step", "follow part", sha256, status codes. A test (`players_never_see_the_services_own_words`) checks that no error text a player sees says relay, mailbox, sync service, token, 429 or 409.
- **First open:** off state and empty state both show 3 numbered steps: invite → they paste the code → share a pack.
- **Every action says what it does** (tooltips on Follow, Share, Join, Decline, Copy, Change, Add a friend, Invite, Stop following, the Following chip). Sharing says who gets it and that only the mod list is sent; the mods download from their own sites.
- **Every state says what's going on and what next:** Friends off ("Turn on friends to share packs…"), can't connect ("Can't connect right now. We'll keep trying."), friend list full, too many open invites, pack removed by the friend, friend removed you.
- **Errors:** `mailbox::says` maps every relay error code (including relay-sec's busy, rate_limited, too_large, group_full, groups_full, group_packs_full, owner_leaves) to a plain sentence; unknown relay errors say "Something went wrong with Friends. Try again in a few minutes."
- **Groups:** the New group dialog says what a group is in one sentence; the switch is "Keep my packs the same as the group".
- **Same-network sync** (old "Sync with a friend" / ⋯ "Friends") is now **Friends nearby** everywhere (title, ⋯ menu, Ctrl+K, settings text), so it isn't confused with the Friends panel. Pair → Connect, Push/Pull → Send to their PC / Get from their PC.

### Confusing flows, not fixed (decide before release)
1. **"Keep my packs the same as the group"** (switch on a group). The helper line says "When someone in the group follows one of its packs, this PC follows it too." A player can't tell which instance changes, whether a new instance appears, or that their own edits get replaced. The toast "Following X's Y, so your packs stay the same as G" doesn't say where either. Suggest: say plainly "Hopper adds a new instance for each pack your group follows" (or whatever it really does) and where to find it.
2. **Leaving a group** says copies "stay on your PC" but not that the packs stay in the Friends list under "These won't change any more" until you tap Stop following. Fine in the panel, silent in the confirm.
3. **What a friend sees** after you share: nothing in the share popover tells you they see the pack in their Friends tab, with a Follow button, and that following replaces their own edits. The Follow chooser says it (good); the sender never learns it.
4. **Pack vs instance**: the Friends panel says "pack", Friends nearby and the share code dialog say "instance" for the same thing ("Follow this instance", "Share this instance with a friend's PC", "Stopped following this instance"). Pick one ("pack").
5. **"Share code" vs "friend code" vs "follow"** : three codes. Friend code (invite, 15 min, once), share code (install a pack, never runs out), and a share code with a "follow" box (also 15 min). The copy explains each in its own place but never side by side; the share dialog's last line "Already friends in Hopper? Share it from the Friends panel instead" helps most.
6. **Friends nearby, advanced bits**: "Tailscale", "port", "100.x.y.z, host:port or https URL". They sit behind "Advanced: address and network", so left as is.
7. **Pack row "N file(s) can't be downloaded from any site"** (panel) gives no next step; the Follow chooser does ("Ask {who} to send …").
8. **"Friend list full" vs "You have as many friends as Hopper allows"** : same limit, two phrasings (both are plain; could be one).
