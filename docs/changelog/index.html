Hopper 0.52.2 · Hopper Server 0.47.2

6 Nov 2026

Versions and changelogs: "Other versions" cards trimmed too

Apps
Both.
Before
0.52.1 trimmed the installed and newer cards, but opening a card under "Other versions" (roll back, older files) still showed its whole cumulative text.
After
Those cards show only their own version's notes, with a collapsed "Earlier versions (N)" row. N counts versions, no longer every line that mentions a version number (the odd "36" before).
  • crates/hopper-core/src/changelog_trim.rs
  • src/gpui/versions.rs
  • crates/hopperd/src/mods_more.rs
  • crates/hopperd/ui/src/ModVersions.svelte
  • crates/hopperd/ui/src/ReviewUpdates.svelte
seen on screen
  • Tests: 16 for the trimming function, including the 5.3.5-file case and headings that mention versions.
  • Seen on screen in both apps with fake data (installed 5.3.4, newer 5.3.6 and 5.3.5, others 5.3.3 and 5.3.2): desktop test build, and a scratch Hopper Server in a real browser.
  • Not checked: real network changelog text, so the count fix is only tested with fixtures; expanding an Other card's "Earlier versions" on desktop; the update review panel (only a parameter added); pack dialogs, which are not trimmed.
  • From now on every UI change gets screenshots of every state in both apps before merge.

Hopper 0.52.1 · Hopper Server 0.47.1

6 Nov 2026

Versions and changelogs: only the notes for each version

Apps
Both: desktop dialog and the Hopper Server web UI. One shared trimming function.
Before
A mod file's changelog that repeats every older release was shown in full. Oh The Trees You'll Grow 5.3.6 listed 5.3.6 down to 5.3.0 and beyond.
After
Each card is cut after its own version's section. The rest sits behind a collapsed "Earlier versions" row. A newer card is also cut at the installed version. If the headings can't be read, the full text is shown, never less.
  • crates/hopper-core/src/changelog_trim.rs
  • crates/hopper-core/src/install.rs
  • crates/hopper-core/src/lib.rs
  • crates/hopperd/src/mods_table.rs
  • crates/hopperd/ui/src/ModVersions.svelte
  • src/gpui/versions.rs
partly checked
  • Tests: 11 for the trimming function (headings, no headings, missing version, the Oh The Trees case). Pass.
  • Desktop: seen on screen with a fake changelog (hack since reverted), installed card only.
  • Web UI: read as page text, no screenshot.
  • Not checked: real network data; the "Other versions" cards (found after release); what "Earlier versions (36)" counts.

Settings: Sleep moves to General

Apps
Both.
Before
Sleep sat under Network & address.
After
Sleep is under General (searchable by "sleep", "wake", "idle"). Network & address has a pointer strip and a "Change in General" button. The wake note says what joining from Minecraft's server list does, or that an address is still needed.
  • src/gpui/panel_tabs/settings.rs
  • crates/hopperd/ui/src/Settings.svelte
  • crates/hopperd/ui/src/Sleep.svelte
  • crates/hopperd/ui/src/Address.svelte
partly checked
  • Seen on screen in both apps against a scratch Hopper Server: Sleep in General, the no-address wake line, the Network pointer, the button opening General. It caught and fixed a pointer that claimed "joining wakes it" with no address.
  • No screenshots were saved.
  • Not checked: the wake wording when an address is set. No tests changed.

Hopper Server 0.46.3

6 Nov 2026

Clear message while a NeoForge server starts

Apps
Hopper Server.
Before
A NeoForge client joining a sleeping server saw "server is not running NeoForge".
After
It sees "<server> is starting: 1%, starting java. Join again in a moment." The player still has to rejoin once the server is up. The router now keeps NeoForge mod data in its saved server answer, and a server with no saved answer counts as modded.
  • crates/hopper-core/src/hosting/router.rs
  • crates/hopperd/src/router.rs
partly checked
  • A new test covers NeoForge, Forge, old FML, flagged and vanilla answers.
  • Live: a real NeoForge client against a scratch vanilla server with no saved answer got the new message, and the router log showed the refuse path.
  • No screenshots saved. Not tried on the real TNP-LL8 server: it needs the new build on rig.
