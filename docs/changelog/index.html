Hopper 0.59.0 · Hopper Server 0.53.1

9 Nov 2026

Big mod lists use far less memory

Apps
Hopper desktop. The Hopper Server web UI's pictures are the browser's own.
Before
Every picture Hopper showed was decoded at full size and kept until Hopper closed: mod icons, instance banners, Browse cards, screenshots and server art. Scrolling a 1,188-mod list ended at about 646 MB working set and 749 MB private.
After
Pictures are decoded no wider than they are shown and kept to a 96 MB budget, dropping the least recently used. The image viewer frees its picture when it closes. The same scroll ends at about 454 MB working set and 548 MB private. Jar scans at start-up use 3 threads instead of 8, and freed memory goes back to Windows: the start-up peak on a copy of a real pack fell from about 529 MB to 433 MB. The same pictures look the same (mean pixel difference 0.21 to 0.36 of 255 in the crops).

Changes in the files: see what changed in a mod version when its author wrote no changelog

Apps
Both: Hopper desktop and the Hopper Server web UI. For a server on a Hopper Server, the desktop does not show this yet: it has no screen for a remote server's mod versions.
Before
A mod version with no changelog just said "No changelog for this version."
After
Off by default. The first version without a changelog in a list offers: "The author didn't write a changelog. Hopper can compare the files to show what changed." with Turn on and Not now. With it on, Hopper compares the old and the new file and lists what visibly changed: new blocks and items, new settings with the author's own description, added languages, changed dependencies, new loot tables and textures. It says plainly that this comes from the files, not the author: "Scanned from the jar files by Hopper, not by the author." If only the mod's code changed it says so, and when only the version details changed it says the files have the same content. It may download one of the two files once, then keeps only a small result. You can turn it on from the notice or in Settings > Mod sources. On Hopper Server only the owner can change the setting; everyone signed in sees the result.

Servers that sleep: modded players can wait on the connecting screen (experimental)

Apps
Hopper Server: a new "Modded players" row in the server's Sleep settings. The same row exists in the desktop Sleep settings for a server on a Hopper Server.
Before
A NeoForge or Forge player who joined a sleeping modded server started it, but was then turned away with a "join again" message.
After
New setting "Modded players" with "Join again message" (the default, as before) and "Wait (experimental)". With Wait, a modded player stays on Minecraft's normal "Connecting to the server..." screen while the server starts and joins by themselves when it is up. There is no progress bar on that screen. Hopper keeps the connection alive, gives up after 10 minutes, and shows the usual "couldn't start" message if the start fails. One connection per player and server, and no more than 16 per server. It only applies when sleep and wake-on-join are on, and it does not change who may wake a server. Vanilla players still wait on the small lobby island.

Updates and syncs replace the old jar, turned-off ones too

Apps
Both: the rule is shared, so Hopper desktop and Hopper Server behave the same, and a remote server gets the same steps over its API.
Before
A sync that found a mod turned off on the server skipped it, so the server never got the new version. Earlier builds put the new jar beside the old turned-off one (the "Old copy" chip). Updating a pack or a mod replaced only the first copy it found, so a mod that already had two copies kept the other one.
After
A sync puts the newer file on the server turned on or off like the copy it replaces (off stays off) and removes the old file. Updating a pack or a single mod replaces every copy of that mod, turned on or off. The new file takes the state of the copy that was on. No older copy is left beside the new one. Mods you added yourself are left alone.

  • crates/hopper-core/src/modpack.rs
  • crates/hopper-core/src/rigsync.rs
  • crates/hopper-core/src/sync.rs
partly checked

Each ended with one file per mod in the right state.
  • No screenshots: there is no visible change except that the sync row now reads as an Update instead of "kept off". Not screenshotted.

Hopper Server: the owner can let a paired PC manage the panel

Apps
Both: Hopper Server (web UI and panel) and Hopper desktop (wording only).
Before
A PC paired through the approval flow was always a plain device. Deleting or removing a server was refused, and the desktop told even the owner to delete it in the panel.
After
When the owner approves a PC, they can tick "Let this PC manage the panel (delete servers, change users)". It is off by default. A device cannot give it to itself, approve other PCs or remove devices. Every approval and switch is written to the audit log. Devices already paired stay off.
