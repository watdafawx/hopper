Hopper 0.55.0 · Hopper Server 0.50.0

8 Nov 2026

Deleting a server: one checkbox, and a clear message when something holds the folder

Apps
Both: Hopper Server (web UI and panel) and Hopper desktop (the dialog and the delete itself).
Before
Deleting a server could fail with "Access is denied" when the panel itself, or another program, held the folder. Deleting for good meant typing the server's name.
After
The panel lets go of its own hold on the folder first and tries the move again a few times. If a program still holds it, the message names that program. A "Delete permanently (can't be undone)" checkbox replaces the typed name: ticked, the dialog says the folder is deleted for good and the button reads "Delete permanently". A setting in Settings > Panel folder chooses which way the dialog starts. If the move fails, nothing is changed, and kept worlds are put back.

  • crates/hopperd/ui/src/RemoveServer.svelte
  • crates/hopperd/ui/src/ServersFolder.svelte
  • src/gpui/server_delete.rs
partly checked
  • Tests for the retry, the message when nobody is found, the path guards (including a junction), the clean-up of leftovers, naming the program that holds a file, and keeping worlds out of a moved folder.
  • Seen on screen in a real browser on a scratch panel with throwaway servers: the default move and restore, a held file naming PowerShell, a hold released during the retry, and delete permanently with the world kept.
  • Not checked: the desktop dialog on screen (it compiles only), rig, Linux and macOS, the exact original failure, and the setting that picks the dialog's start with the checkbox version.
  • No before screenshots (the old build was not run).

Count badges: the digits sit centred at every zoom level

Apps
Both: the Updates icon in the Mods filter row and the History button in Hopper, and the same badges in Hopper Server.
Before
At 125 % zoom the digits of the Updates badge sat 1 px from the top and 3 px from the bottom. At 175 % and 200 % the badge was no taller than its digits, which spilled out.
After
The badge grows with the zoom and the digits are placed by the font's own height. Top and bottom gaps match (within 1 px) from 67 % to 200 %, for both badges, in three themes. In Hopper Server the digits are within 1 px at page zoom 100 % to 200 %.

  • src/gpui/history_button.rs
  • crates/hopperd/ui/src/app.css
  • crates/hopperd/ui/src/Mods.svelte
  • crates/hopperd/ui/src/HistoryButton.svelte
partly checked
  • A new test checks that the badge is whole pixels with a balanced gap at every zoom.
  • Gaps measured on screenshots of a running test build at zoom 67 % to 200 %, in Catppuccin Mocha, Hopper Dark and Hopper Light, with the counts faked on a throwaway instance. The web badge was measured in headless Chrome on a test page with the real stylesheet, not in the live panel.
  • Not checked: Firefox and Safari (they keep the old centring), real instances, screens with a scale other than 100 %, and the History badge with two digits.
  • The digits can sit up to 2 px off sideways when the number starts with a 1 or has a +. Not changed.

Browse: the arrow keys keep going when the next page of results loads

Apps
Hopper desktop only. Hopper Server's Browse has no arrow-key list.
Before
Pressing Down on the last loaded row could stall when the next page held rows that were already listed.
After
The next page starts after what the server has already handed over, and Down keeps asking until a new row exists, then picks it.

Hopper 0.54.0 · Hopper Server 0.49.0

7 Nov 2026

Appearance in the title bar: themes, zoom and two switches without opening Settings

Apps
Both. Zoom, Still header, Smooth scrolling and "Yours" are in Hopper only.
Before
Changing the theme, zoom, Still header or Smooth scrolling meant Settings > Appearance. Hopper Server's web UI had no theme choice at all.
After
A palette button next to the gear (Ctrl+Shift+A in Hopper) opens a panel. Themes are grouped Follow Windows, Dark, Light and Yours. Resting on a theme previews it on the whole app; a click keeps it; Esc, moving away or clicking outside puts the saved theme back. The panel also has Zoom, Still header, Smooth scrolling, a button for the themes folder, a reload button and a link to all appearance settings. Arrow keys move through the themes. The choice in Hopper Server is remembered per browser.

partly checked
  • Tests for the preview rules, arrow-key moves, saved theme name, zoom steps, the order of the sections, and that the web theme list equals the desktop palettes.
  • Seen on screen in both apps (a scratch copy of Hopper and a scratch Hopper Server in a real browser): hover preview in a dark and a light theme, Esc and moving away undoing it, arrow keys, zoom, both switches, reloading with a second theme file, Follow Windows, a restart keeping the settings, and narrow windows.

Hopper Server: pages no longer ask the panel for the same thing every second

Apps
Hopper Server web UI and the panel's log. One small fix in Hopper desktop.
Before
Opening any server page made the browser ask the panel for the last crash every second, and Worlds, Data packs and Settings > Sleep did the same for their own data. Nothing stopped a loop until the panel's "Too many requests" limit, after about 1,200 requests.
After
Those pages load once and again only when something really changed; an idle server page now makes about 40 to 70 requests a minute instead of 110 to 180. A page that starts looping is stopped in the browser and shows "This page is asking too often, paused it". The panel logs a warning at 80% of its limit. In Hopper, leaving the Servers page now stops its per-server checking.

partly checked

  • Request counts measured in a real browser on a scratch panel for most pages, before and after, and the old Sleep page was shown looping and then stopped.
  • Not checked: the Hopper fix on screen (it compiles only), a hidden browser tab, a few pages after the fix (Memory & Java, All properties, New server, Trash, Spark), and proxy traffic.
  • No screenshots: the result is request counts, not a visible change.
