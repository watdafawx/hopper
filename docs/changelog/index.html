Server packs made on Windows now start on Linux and macOS

Apps
Both. Hopper desktop and Hopper Server read the start command with the same code.
Before
On Linux, starting a NeoForge or Forge pack made on Windows ran the Windows arguments file. That file lists the mods with semicolons, so Java stopped with "Could not find or load main class cpw.mods.bootstraplauncher.BootstrapLauncher".
After
On Linux and macOS the pack runs its unix arguments file instead, and on Windows a pack that names the unix file gets the Windows one. If the other file is missing, the named one is used as before. The pack's own run and start scripts are left exactly as written, so they still work on the PC they came from.

Hopper Server updates itself on Linux

Apps
Hopper Server. Hopper desktop has no server self-update.
Before
On Linux the Update button and automatic updates were off: the panel said it updates itself on Windows only.
After
Linux panels on x64 and arm64 update like Windows ones: download, restart into the new version, and roll back from Other versions. It waits only while a server started by an older version is still running. Each download is checked against the SHA-256 fingerprint GitHub lists for that file, not just its size; a file that does not match is refused with a plain message and nothing is installed. Linux also checks that the file is a program for its own kind of machine.

Hopper Server on Linux. Hopper desktop uses the same process code but only runs on Windows, and Windows behaves as before.
Before
After a Linux panel restarted (an update, a crash or a service restart), servers that were running became orphans: no console, no commands, no stop. A Linux update therefore had to wait for every server to stop.

Only servers started by an older panel still hold an update back and offer "Stop servers and update" or "Wait for them to stop"; those servers need one stop and start before the panel can take them over.
